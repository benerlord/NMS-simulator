# 节点类型搜索与网管/设备作用域 — 设计方案（修订版）

## 问题分析

### 问题 1：画布左侧面板无法查找节点类型

**现状**：`TypePalette.vue` 加载全局所有节点类型，按 `category` 分组展示为可拖拽列表。无搜索或筛选功能。

**痛点**：节点类型数量增多后（30-50+），用户需逐行扫描查找，效率极低。

### 问题 2：无法区分"节点类型属于哪个网管环境"

**现状**：`node_types` 是全局平铺表，所有拓扑共享同一套类型。

**痛点**：本工具需模拟**多个不同网管环境**（如"华为 NMS" vs "思科 NMS"），且**多个拓扑可能属于同一个网管环境**。例如：

- 北京网管下有 3 个拓扑：`北京-核心网`、`北京-接入网`、`北京-骨干网`
- 上海网管下有 2 个拓扑：`上海-核心网`、`上海-接入网`
- 北京网管有"华为交换机"节点类型，上海网管没有
- 北京的 3 个拓扑**共享同一套**节点类型，上海的 2 个拓扑共享另一套

当前设计下，打开任意拓扑的画布，都会看到全部 5 个拓扑的所有类型混在一起。

**核心矛盾**：拓扑 ≠ 网管环境。一个网管环境可以包含多个拓扑。需要在拓扑之上增加一层抽象。

---

## 设计目标

1. TypePalette 支持**下拉搜索**（输入时动态匹配并更新下拉选项）
2. 节点类型按**网管环境**（域）控制可用性
3. **多个拓扑可共享同一个域**的类型配置
4. 向后兼容，已有数据不受影响

---

## 方案设计

### 整体思路

新增 **域（domain）** 作为顶层抽象。拓扑归属于域，节点类型也关联到域。画布面板只展示当前拓扑所属网管/设备下的节点类型。

```
┌──────────┐     ┌──────────────┐     ┌────────────────────┐     ┌──────────────┐
│  domain  │     │  topologies  │     │ domain_node_types  │     │  node_types  │
│          │ 1:N │              │     │                    │ N:1 │              │
│  id      │◄────│  domain_id   │     │  domain_id         │────►│  id          │
│  name    │     │  id          │     │  node_type_id      │     │  code        │
│  desc    │     │  name        │     │                    │     │  name        │
└──────────┘     │  ...         │     └────────────────────┘     │  ...         │
                 └──────────────┘                                └──────────────┘
```

**关系梳理**：

| 实体 | 含义 | 举例 |
|------|------|------|
| domain | 一个网管环境 / 设备域 | "北京网管"、"思科 NMS" |
| topology | 该网管下的一个画布场景 | "北京-核心网拓扑" |
| node_type | 设备/对象类型定义 | "华为交换机"、"思科路由器" |
| domain_node_types | 域内可用的类型白名单 | 北京域可用华为交换机、华为路由器 |

**查询链**：打开画布 → 查 topology 的 domain_id → 查 domain_node_types → 返回该域的节点类型列表。

### 为什么选择 domain 表而非拓扑级 scoping？

| 考量 | 域表（domain） | 拓扑级 M2M |
|------|:-----------:|:-----------:|
| 多拓扑共享类型 | ✅ 天然支持 | ❌ 每个拓扑各自配，重复劳动 |
| 语义清晰 | ✅ 域 = 网管环境 | ❌ 拓扑承担两重含义 |
| 迁移成本 | 中（1 新表 + topology 加 1 列） | 低（1 M2M 表） |
| 扩展性 | ✅ 后续可加域级设置 | ❌ 受限于拓扑粒度过细 |

domain 方案更贴近实际使用场景，"北京网管的 3 个拓扑共享一套类型"是合理的需求。

## 实现设计

### 1. 数据库

**新增表 `domains`：**

```sql
CREATE TABLE IF NOT EXISTS domains (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL UNIQUE,
  description TEXT,
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
```

**新增表 `domain_node_types`：**

```sql
CREATE TABLE IF NOT EXISTS domain_node_types (
  domain_id     TEXT NOT NULL,
  node_type_id  TEXT NOT NULL,
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (domain_id, node_type_id),
  FOREIGN KEY (domain_id) REFERENCES domains(id) ON DELETE CASCADE,
  FOREIGN KEY (node_type_id) REFERENCES node_types(id) ON DELETE CASCADE
);
```

**`topologies` 表新增列：**

```sql
ALTER TABLE topologies ADD COLUMN domain_id TEXT;
-- 不设 FK 约束，允许 NULL 保持向后兼容
```

### 2. 后端 API

#### 2.1 Domain CRUD — `domains` 路由

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/domains` | 域列表 |
| POST | `/domains` | 创建域 |
| PUT | `/domains/{id}` | 编辑域 |
| DELETE | `/domains/{id}` | 删除域（级联清理 domain_node_types） |

#### 2.2 NodeType-Domain 关联（从节点类型侧操作）

关联操作在**节点类型管理页面**进行，支持单个和批量两种方式。

| 方法 | 路径 | 说明 |
|------|------|------|
| PUT | `/node-types/{id}/domains` | 单个节点类型设置域 `{ "domainIds": ["dom_xxx", ...] }` |
| PUT | `/node-types/domains` | **批量**关联/解除 `{ "nodeTypeIds": [...], "domainIds": [...] }` |

逻辑：
- `domainIds` 非空 → 对列表中所有节点类型**统一设置**这些域（全量替换）
- `domainIds: []` → 清空所有网管/设备关联，类型变为**全局可用**（批量解除）

#### 2.3 修改 `GET /node-types` — 支持 domain_id 过滤

```
GET /admin/api/node-types?domain_id=dom_xxx
```

**逻辑**：
- 不带 `domain_id` → 返回全部类型（与现状一致，供管理页面使用）
- 带 `domain_id` → 查询 `domain_node_types`：
  - 如果该域有绑定记录 → 只返回绑定的类型
  - 如果该域无任何绑定记录 → 返回全部类型（向后兼容，默认全部可用）

#### 2.4 Topology 相关

- `POST /topologies` 创建时支持可选 `domain_id` 参数
- `PUT /topologies/{id}` 支持修改 `domain_id`
- `GET /topologies/{id}` 返回 `domain_id`

### 3. 前端

#### 3.1 TypePalette.vue — 下拉搜索 + 域过滤

**交互设计**：

```
┌──────────────────────────────────┐
│  🔍 输入关键字搜索...         ▼  │  ← AutoComplete 下拉输入框
├──────────────────────────────────┤
│  ▸ 交换机  switch   物理设备      │  ← 下拉选项动态匹配
│  ▸ 路由器  router   物理设备      │
│  ▸ 云交换机 cloud-sw 云资源       │  ← 输入"云"实时过滤
├──────────────────────────────────┤
│  物理设备 (12)                    │  ← 分组标题（收折）
│  ▸ 交换机         switch          │  ← 可拖拽项
│  ▸ 路由器         router          │
│  ...                              │
│  云资源 (5)                       │
│  ▸ 宿主机         hypervisor      │
│  ...                              │
└──────────────────────────────────┘
```

**实现要点**：

| 功能 | 实现 |
|------|------|
| 搜索输入 | Ant Design `AutoComplete` 组件 + `allowClear` |
| 下拉匹配 | `filterOption` 属性对 name / code / category 做模糊匹配 |
| 选中定位 | 选中下拉项后，下方列表中高亮并 `scrollIntoView` 对应项 |
| 数据加载 | `fetchNodeTypes({ domainId })` 传入当前拓扑的域 ID |

**搜索匹配规则**：
- 匹配节点类型的 **名称**（如"交换机"、"核心路由器"）
- 匹配节点类型的 **编码**（如"switch"、"router"）
- 匹配节点类型的 **分类**（如"物理设备"、"云资源"）
- 支持**任意位置子串匹配**（"交换" 匹配 "交换机"、"光交换"）

#### 3.2 CanvasView.vue — 传递 domainId 给 TypePalette

```html
<!-- 改动前 -->
<TypePalette />

<!-- 改动后 -->
<TypePalette :domain-id="topology?.domainId" />
```

`topology` 数据从当前画布的拓扑详情中获取。如果 `domainId` 为空（旧拓扑未绑定域），则行为不变——展示全部类型。

#### 3.3 节点类型管理页面 — 网管/设备关联入口（NodeTypeTable.vue）

关联操作放在类型管理页面，支持**单个**和**批量**两种方式。

**批量操作交互**：

```
1. 勾选多个节点类型（使用现有多选框）
2. 点击工具栏"批量操作"按钮 → 下拉菜单展示所有可用操作
3. 选择具体操作 → 弹出对应弹窗/确认框
4. 确认 → 调用对应 API
5. 刷新表格
```

**下拉菜单项**：

```
┌──────────────────────────────────────────────────────────────────┐
│  已选 3 项    [批量操作 ▾]                           [导出] [导入]│
│              ┌─────────────────┐                                 │
│              │ 🔗 关联网管/设备        │  → 弹出域多选弹窗               │
│              │ ✂  解除关联      │  → 弹出确认框（仅已关联类型可见）│
│              │ 🗑  批量删除      │  → 弹出现有二次确认框           │
│              └─────────────────┘                                 │
└──────────────────────────────────────────────────────────────────┘
```

**菜单项逻辑**：

| 菜单项 | 出现条件 | 行为 |
|--------|---------|------|
| 关联网管/设备 | 至少选中 1 项 | 弹出域多选下拉弹窗 → `PUT /node-types/domains` |
| 解除关联 | 至少选中 1 项，且其中至少 1 项已有网管/设备关联 | 弹出确认框 → `PUT /node-types/domains` 带 `domainIds: []` |
| 批量删除 | 至少选中 1 项 | 弹出现有二次确认框（已有功能，不变） |

**导出/导入保持独立按钮**：因为它们是独立于勾选的功能（无需选中项即可操作），不与批量操作合并。

**单个关联**：点击某个类型的"所属网管/设备"列的 Tag，弹出编辑弹窗直接修改。

**"所属网管/设备"列展示**：
- 有关联：`<Tag closable>` 展示域名称，可逐一点击 `x` 移除
- 无关联：`-`（该类型全局可用）

#### 3.4 网管/设备管理页面（新增 `DomainsView.vue`）

纯粹做域本身的 CRUD，不做类型绑定。

| 功能 | 说明 |
|------|------|
| 域 CRUD 列表 | 表格展示所有域 name / description / 拓扑数，支持新建/编辑/删除 |
| 拓扑归属 | 显示该域下有多少个拓扑引用 |

#### 3.5 拓扑编辑弹窗（TopologyModal.vue）

新增 `domain_id` 选择器（下拉选择已有域，可留空 = 无限制）。

### 4. 向后兼容策略

| 场景 | 行为 |
|------|------|
| `topology.domain_id = NULL`（旧拓扑） | TypePalette 展示全部类型，行为与现状一致 |
| `domain_node_types` 为空（域未配置类型） | 展示全部类型，等同于未限制 |
| `domain_node_types` 有记录（域已配置类型） | 仅展示绑定的类型（白名单模式） |
| 管理页面 `GET /node-types` 不带 `domain_id` | 始终返回全部类型，供管理页使用 |

### 5. 默认种子数据

```python
# seed.py 新增
DOMAINS: list[dict] = []

# 不预置 seed 域 —— 用户按需创建
# 域 ID 前缀：dom_ + uuid12（遵循项目 ID 前缀规则）
```

## 备选方案对比（更新）

| | 方案 A：domain 表（推荐） | 方案 B：拓扑级 M2M | 方案 C：category 枚举 |
|---|---|---|---|
| 多拓扑共享类型 | ✅ domain 下所有拓扑自动共享 | ❌ 每个拓扑各自配置 | ❌ 类型只能属于一个 category |
| 新增"上海网管" | 建一个 domain，拓扑选归属 | 每个新拓扑逐一手动配类型 | 修改类型 category |
| 表结构改动 | 2 新表 + 1 列 | 1 新表 | 0 |
| 语义匹配 | ✅ 域 = 网管环境 | ❌ 拓扑身兼二职 | ❌ category 表达域含义牵强 |
| 实施成本 | 中（约 12 文件） | 低（约 6 文件） | 极低 |

**推荐方案 A**：符合"多个拓扑属于同一个网管环境"的实际需求，且"域"概念语义清晰、可扩展。
