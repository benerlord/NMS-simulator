## 1. 架构总览

### 1.1 部署拓扑

```
┌─────────────────────────┐        ┌──────────────────────────┐
│  浏览器（测试工程师）     │        │  MindOps 采集插件         │
└───────────┬─────────────┘        └──────────────┬───────────┘
            │                                     │
            │ HTTP / WebSocket                    │ HTTP（用户自定义接口）
            ▼                                     │
┌──────────────────────────┐                      │
│  前端静态资源              │                      │
│  Nginx（或 Vite dev）     │                      │
│  · Vue 3 SPA             │                      │
└───────────┬──────────────┘                      │
            │ REST + WS                           │
            │ /admin/api/**                       │ <api_configs.path>
            ▼                                     ▼
┌─────────────────────────────────────────────────────────────┐
│            后端服务（FastAPI · 独立部署）                      │
│  ┌──────────────────────┐   ┌──────────────────────────┐    │
│  │  管理子应用           │   │  模拟子应用                │    │
│  │  /admin/api/*         │   │  <api_configs.path>      │    │
│  │  · 拓扑 CRUD          │   │  · 动态路由分发            │    │
│  │  · 接口配置 CRUD      │   │  · 启用校验                │    │
│  │  · Token 管理          │   │  · 认证 / 异常注入         │    │
│  │  · WebSocket 推送     │   │  · SQL / 静态响应          │    │
│  └──────────┬───────────┘   └──────────┬───────────────┘    │
│             └─────────────┬────────────┘                    │
│                           ▼                                 │
│                    SQLite（./data/app.db）                   │
└─────────────────────────────────────────────────────────────┘
```

> **路径前缀约定**：模拟子应用默认**无统一前缀** —— `api_configs.path` 直接挂载在根路径下（如 `GET /rest/openapi/network/v1/devices`），便于复刻原系统的 URL。如需统一前缀，把 `settings.mock_path_prefix` 改成 `/mock` 等任意值即可（默认空串）。本文档其它位置出现的 `/mock/**` 仅作示意符号，对应的真实路径以 `mock_path_prefix + api_configs.path` 拼接。

### 1.2 设计决策摘要

| 决策 | 选择 | 理由 |
|------|------|------|
| **前后端部署** | 独立部署 | 前端可独立发版；后端可无 UI 运行 |
| **后端形态** | 单进程 FastAPI，路径前缀区分管理/模拟 | 最简；后期如需端口隔离可低成本迁移 |
| **数据层** | SQLite 唯一数据源，无内存副本 | 3 万设备量级 SQLite 足够快；架构简洁 |
| **前端形态** | Vue 3 SPA | 强交互画布场景天然适合 |
| **实时通信** | WebSocket（保存状态 / 接口路由变更推送） | 统一通道，体验一致 |
| **鉴权** | MVP 不做管理鉴权（内网信任） | 符合 PRD 非目标 |
| **SQL 安全** | 仅允许 SELECT / WITH | 防止误改数据 |

## 3. 后端模块划分

### 3.1 子应用切分

```
FastAPI App
├── /admin/api/**     →  AdminApp（管理子应用）
│   ├── /topologies        拓扑场景管理
│   ├── /device-types      设备类型管理
│   ├── /apis              接口配置管理
│   ├── /tokens            Token 管理
│   ├── /settings          系统设置
│   └── /ws                WebSocket 推送
└── <mock_path_prefix><api_configs.path>  →  MockApp（模拟子应用，动态路由；默认 mock_path_prefix="" 即根路径）
```

### 3.2 核心模块

| 模块 | 职责 |
|------|------|
| **TopologyService** | 拓扑场景、设备、端口、链路的 CRUD；场景导入 / 导出；历史版本（保留 3 个） |
| **DeviceTypeService** | 全局设备类型的定义与字段管理 |
| **ApiConfigService** | 接口配置 CRUD；接口-拓扑绑定关系维护；启用开关 |
| **RouteRegistry** | 维护模拟子应用的动态路由表（前缀 `settings.mock_path_prefix`，默认空串）；接口变更时实时同步 |
| **RequestPipeline** | 请求处理管道：路由匹配 → 启用校验 → 认证 → 异常注入 → 查询 → 响应渲染 |
| **SqlQueryExecutor** | 基于绑定拓扑场景执行只读 SQL；参数绑定；自动分页；语句白名单校验 |
| **ResponseRenderer** | 响应模板渲染；占位符替换（`{{items}}`、`{{uuid}}` 等） |
| **TokenManager** | Token 注册表管理（CRUD）+ Pipeline 校验（已颁发 token 是否有效） |
| **AutoSaver** | 60s 定时自动保存；退出前提示 |
| **SettingsService** | 端口、数据路径、日志级别等系统设置 |
| **WebSocketHub** | 统一 WebSocket 通道，推送保存状态与接口路由变更事件 |

## 4. 数据模型（SQLite）

### 4.1 表清单

| 表名 | 用途 |
|------|------|
| `topologies` | 拓扑场景主表 |
| `topology_history` | 拓扑场景历史版本（每场景保留 3 个） |
| `device_types` | 全局设备类型定义 |
| `devices` | 设备（归属某个拓扑场景） |
| `ports` | 端口（归属某个设备） |
| `links` | 链路（连接两个端口） |
| `canvas_nodes` | 画布坐标等视觉信息 |
| `api_configs` | 接口配置（含启用开关、拓扑绑定） |
| `tokens` | 全局 Token 表 |
| `settings` | 系统设置键值表 |

### 4.2 关键字段与关系

- `devices.topology_id → topologies.id`
- `ports.device_id → devices.id`
- `links.source_port_id / target_port_id → ports.id`
- `api_configs.topology_id → topologies.id`（可空：静态模式可不绑定）
- `api_configs.enabled` 布尔
- `api_configs.method + path` 联合唯一

### 4.3 数据一致性

- 删除拓扑：若 `api_configs` 中存在引用，**阻止删除**并返回占用列表
- 删除设备：级联删除其端口；涉及的链路一并删除
- 删除端口：涉及的链路一并删除

## 5. 接口运行时（mock 子应用）

> 路径形如 `<mock_path_prefix><api_configs.path>`；默认 `mock_path_prefix=""`，此时调用方直接 `curl <api_configs.path>` 命中。

### 5.1 请求处理管道

```
请求进入 mock 子应用
   │
   ▼
[1] 路由匹配       → RouteRegistry 查找 method+path
   │
   ▼
[2] 启用校验       → enabled=false 返回 404
   │
   ▼
[3] 认证校验       → 根据 auth 类型（none/xtoken/basic）校验
   │
   ▼
[4] 异常注入       → 延迟 / 按概率返回错误码
   │
   ▼
[5] 查询执行       →  sql 模式：参数绑定 → count → 分页 → 执行
                      static 模式：读取 JSON + 占位符渲染
   │
   ▼
[6] 响应渲染       → 模板替换 → 返回给采集插件
```

### 5.2 SQL 模式执行细节

- **白名单**：仅允许首关键字为 `SELECT` 或 `WITH`（去除首部注释 / 空白后判断）
- **参数绑定**：URL query 参数按配置映射到 SQL 命名参数 `:paramName`
- **自动分页**：
  1. `SELECT COUNT(*) FROM (<用户 SQL>)` 得到 `total`
  2. `<用户 SQL> LIMIT :pageSize OFFSET :offset`
- **作用域隔离**：查询时注入 `WHERE topology_id = <绑定场景 id>`（或通过视图限定），保证接口只能看到绑定场景的数据

### 5.3 动态路由同步

| 触发事件 | RouteRegistry 行为 |
|----------|-------------------|
| 新增接口 | 注册路由 |
| 编辑接口（method / path 变化） | 卸载旧路由 + 注册新路由 |
| 编辑接口（仅其他字段变化） | 更新路由绑定的配置引用 |
| 启用 / 禁用 | 不动路由表，在管道 [2] 步校验 |
| 删除接口 | 卸载路由 |
| 拓扑绑定切换 | 更新引用；下次请求即命中新场景 |

## 6. 前端结构

### 6.1 页面路由

| 路径 | 页面 |
|------|------|
| `/` | 跳转至 `/topologies` |
| `/topologies` | 拓扑列表 |
| `/topologies/:id` | 拓扑编辑器 |
| `/apis` | 接口列表 |
| `/apis/:id` | 接口配置编辑（SQL 编辑器 / 响应模板 / 测试执行） |
| `/data` | 设备 / 端口 / 链路只读查看 |
| `/settings` | 系统设置 |

### 6.2 状态管理

- `topologyStore`：当前打开的多个拓扑场景（支持多 Tab 并行编辑）
- `apiStore`：接口配置列表与编辑态
- `systemStore`：服务状态、端口、WS 连接

## 7. WebSocket 通道

## 8. 配置与交付

### 8.1 目录结构（建议）

```
InterfaceTest/
├── backend/
│   ├── app/
│   │   ├── admin/         管理子应用
│   │   ├── mock/          模拟子应用
│   │   ├── core/          模块实现
│   │   ├── models/        Pydantic + 数据访问
│   │   └── main.py
│   ├── requirements.txt
│   └── .env.example
├── frontend/
│   ├── src/
│   ├── package.json
│   └── vite.config.ts
├── data/
│   └── app.db             运行时生成
├── docs/
├── start.bat
└── start.sh
```

### 8.2 环境变量（`.env`）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `APP_HOST` | `0.0.0.0` | 监听地址 |
| `APP_PORT` | `8080` | 后端端口 |
| `DB_PATH` | `./data/app.db` | SQLite 文件路径 |
| `LOG_LEVEL` | `INFO` | 日志级别 |
| `AUTOSAVE_INTERVAL` | `60` | 自动保存间隔（秒） |
| `HISTORY_KEEP` | `3` | 历史版本保留数 |

### 8.3 启动脚本

- `start.sh` / `start.bat`：启动 `uvicorn app.main:app --host $APP_HOST --port $APP_PORT`
- 前端开发：`pnpm dev`；前端交付：`pnpm build` 后用 Nginx 托管 `dist/`

## 9. 非功能设计

| 维度 | 目标 | 设计措施 |
|------|------|----------|
| **性能** | 分页查询 < 1s（3 万设备） | SQLite 建立 `devices.topology_id`、`ports.device_id`、`links.source/target_port_id` 索引 |
| **数据安全** | 防意外丢失 | 60s 自动保存；历史版本保留 3 个；退出前提示 |
| **简单部署** | 一键启动 | pip 安装 + 启动脚本；前端静态托管 |
| **可扩展** | 预留协议扩展 | 模拟子应用与管理子应用解耦；后续 SNMP/SFTP/Kafka 可作为独立子应用接入 |

## 10. MVP 不做项（架构层面）
