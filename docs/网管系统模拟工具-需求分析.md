# 网管系统模拟工具 - 需求分析文档

## 1. 项目概述

### 1.1 项目目标

开发一个可扩展的网管系统模拟工具，用于测试 MindOps 采集纳管插件的数据采集功能。

### 1.2 适用范围

- 模拟的网管系统：ManageOne、eSight
- 支持的协议：HTTP、SNMP、SFTP、Kafka
- 采集的数据类型：设备资源、告警、指标
- 配置方式：图形化拓扑配置 + Web 界面配置
- 使用场景：个人开发/测试环境，单用户使用，低并发场景

### 1.3 设计原则

- **拓扑驱动数据**：所有设备、端口、链路数据从拓扑图中产生，画拓扑即生成数据
- **配置驱动接口**：HTTP 接口通过 Web 界面配置，不需要修改代码
- **内存优先查询**：HTTP 接口响应直接使用内存中的拓扑数据，不查询数据库
- **延迟批量保存**：拓扑数据在内存中编辑，统一保存时同步到数据库
- **数据安全保障**：提供自动保存、版本管理、导出备份等机制防止数据丢失

### 1.4 核心使用流程

```
画拓扑（产生数据） → 配接口（暴露数据） → 启服务 → 插件对接采集
```

### 2.2 数据流

```
拓扑编辑器（前端）
    │
    ▼
TopologyManager（内存）
    │
    ├──→ HTTP 接口：RouteDispatcher → QueryPipeline → ResponseRenderer

    ├──→ Kafka 消息：定时从内存构建消息发送

```

## 3. 功能需求

### 3.1 图形化拓扑配置模块

拓扑编辑器是整个系统的数据源头，所有设备、端口、链路数据从拓扑图中产生。

### 3.2 HTTP 接口配置模块

HTTP 接口通过 Web 界面配置，配置保存后动态注册路由，无需重启服务。

#### 3.2.1 接口配置引擎

每个 HTTP 接口由一份配置完整定义，数据源默认使用 SQL 模式：

```javascript
{
  id: "api_001",
  name: "设备查询接口",
  enabled: true,
  group: "ManageOne",

  // ── 路由匹配 ──
  method: "GET",
  path: "/rest/openapi/network/v1/devices",

  // ── 认证 ──
  auth: {
    type: "xtoken",            // none | xtoken | basic
    headerName: "X-Auth-Token"
  },

  // ── 数据源（默认 sql） ──
  dataSource: {
    type: "sql",               // sql | static
    sql: "SELECT * FROM devices"
  },

  // ── 查询参数绑定 ──
  query: {
    params: [
      { param: "type",   sqlParam: ":type",   default: null },
      { param: "status", sqlParam: ":status", default: null }
    ],
    pagination: {
      enabled: true,
      pageNoParam: "pageNo",
      pageSizeParam: "pageSize",
      defaultPageSize: 100
    }
  },

  // ── 响应模板 ──
  response: {
    contentType: "application/json",
    template: {
      code: 0,
      data: "{{items}}",
      total: "{{total}}",
      pageNo: "{{pageNo}}",
      pageSize: "{{pageSize}}"
    }
  },

  // ── 异常模拟 ──
  fault: {
    delay: 0,
    errorRate: 0,
    errorStatus: 500
  }
}
```

#### 3.2.2 两种数据源模式

| 模式 | 配置方式 | 适用场景 |
|------|---------|---------|
| **sql**（默认） | SQL 编辑器编写查询，查询内存虚拟表 | 所有数据查询接口（设备、端口、链路、告警、指标、聚合统计等） |
| **static** | 直接填写 JSON 响应体 | 固定响应（认证接口、系统信息接口等） |

#### 3.2.3 SQL 数据源模式（默认）

新建接口时，数据源默认为 SQL 模式。用户选择数据集合后，系统自动填充默认 SQL，用户可在此基础上修改：

**虚拟表（内存拓扑数据注册为 SQL 可查询的表）：**

| 虚拟表名 | 数据来源 | 默认 SQL |
|----------|---------|---------|
| `devices` | 内存中的设备数据 | `SELECT * FROM devices` |
| `ports` | 内存中的端口数据 | `SELECT * FROM ports` |
| `links` | 内存中的链路数据 | `SELECT * FROM links` |
| `alarms` | 内存中的告警数据 | `SELECT * FROM alarms` |
| `metrics` | 内存中的指标数据 | `SELECT * FROM metrics` |

**默认 SQL 自动填充规则：**

用户在界面上选择数据集合时，SQL 编辑器自动填充对应的默认查询：

- 选择「设备」→ 填充：
  ```sql
  SELECT * FROM devices
  ```
- 选择「端口」→ 填充：
  ```sql
  SELECT * FROM ports
  ```
- 选择「链路」→ 填充（自动带 JOIN 关联 DN）：
  ```sql
  SELECT
    l.*,
    d1.name AS sourceDeviceName,
    d1.dn   AS sourceDeviceDn,
    p1.name AS sourcePortName,
    p1.dn   AS sourcePortDn,
    d2.name AS targetDeviceName,
    d2.dn   AS targetDeviceDn,
    p2.name AS targetPortName,
    p2.dn   AS targetPortDn
  FROM links l
    JOIN devices d1 ON l.sourceDeviceId = d1.id
    JOIN ports   p1 ON l.sourcePortId   = p1.id
    JOIN devices d2 ON l.targetDeviceId = d2.id
    JOIN ports   p2 ON l.targetPortId   = p2.id
  ```
- 选择「告警」→ 填充（自动关联设备信息）：
  ```sql
  SELECT
    a.*,
    d.name AS deviceName,
    d.dn   AS deviceDn
  FROM alarms a
    JOIN devices d ON a.deviceId = d.id
  ```
- 选择「指标」→ 填充（自动关联设备信息）：
  ```sql
  SELECT
    m.*,
    d.name AS deviceName,
    d.dn   AS deviceDn
  FROM metrics m
    JOIN devices d ON m.deviceId = d.id
  ```

默认 SQL 填充后，用户可自由修改：添加 WHERE 条件、调整 SELECT 字段、增加 JOIN、添加 ORDER BY 等。

**SQL 查询参数绑定：**

URL 参数通过命名参数 `:paramName` 绑定到 SQL 中，实现动态过滤：

```javascript
// 接口配置
query: {
  params: [
    { param: "type",   sqlParam: ":type",   default: null },
    { param: "status", sqlParam: ":status", default: null },
    { param: "name",   sqlParam: ":name",   default: null }
  ]
}
```

```sql
-- SQL 中使用命名参数
SELECT * FROM devices
WHERE (:type IS NULL OR type = :type)
  AND (:status IS NULL OR status = :status)
  AND (:name IS NULL OR name LIKE '%' || :name || '%')
```

请求 `GET /api/devices?type=switch&pageNo=1&pageSize=50` 时：
- `:type` 绑定为 `'switch'`
- `:status` 绑定为 `NULL`（未传参，使用 default）
- `:name` 绑定为 `NULL`
- 系统自动追加 `LIMIT 50 OFFSET 0`，自动计算 total

**分页处理：**

分页由系统自动处理，无需用户在 SQL 中手写 LIMIT/OFFSET：

| 步骤 | 说明 |
|------|------|
| 1. 执行 count 查询 | 将用户 SQL 包装为 `SELECT COUNT(*) FROM (用户SQL)` 获取 total |
| 2. 追加分页子句 | 在用户 SQL 末尾追加 `LIMIT :pageSize OFFSET :offset` |
| 3. 执行分页查询 | 返回当前页数据 |

用户也可以在 SQL 中自行编写 LIMIT/OFFSET 关闭自动分页（当 pagination.enabled = false 时）。

**SQL 能力总结：**

| 能力 | 说明 |
|------|------|
| **JOIN 关联** | 通过 SQL JOIN 自动关联设备、端口、链路的 DN，无需特殊语法 |
| **过滤排序** | WHERE 条件过滤 + ORDER BY 排序，完全由 SQL 控制 |
| **聚合统计** | GROUP BY / COUNT / SUM / AVG 等聚合函数 |
| **子查询** | 支持嵌套查询 |
| **字段重命名** | SELECT 中用 AS 别名直接定义输出字段名 |
| **命名参数** | `:paramName` 绑定 URL 参数，防止 SQL 注入 |
| **自动分页** | 系统自动追加 LIMIT/OFFSET，自动计算 total |
| **测试执行** | 配置界面提供「测试执行」按钮，实时预览查询结果 |
| **默认填充** | 选择数据集合后自动填充带 JOIN 的默认 SQL，降低使用门槛 |

**SQL 自定义示例：**

在默认 SQL 基础上添加过滤和排序：
```sql
SELECT * FROM devices
WHERE (:type IS NULL OR type = :type)
  AND (:status IS NULL OR status = :status)
ORDER BY name ASC
```

按类型统计设备数量：
```sql
SELECT type AS deviceType, COUNT(*) AS count
FROM devices
GROUP BY type
ORDER BY count DESC
```

链路查询（默认 SQL 已带 JOIN，可直接使用或追加条件）：
```sql
SELECT
  l.id AS linkId,
  d1.dn AS srcDeviceDn,
  p1.dn AS srcPortDn,
  d2.dn AS dstDeviceDn,
  p2.dn AS dstPortDn,
  l.bandwidth,
  l.status
FROM links l
  JOIN devices d1 ON l.sourceDeviceId = d1.id
  JOIN ports   p1 ON l.sourcePortId   = p1.id
  JOIN devices d2 ON l.targetDeviceId = d2.id
  JOIN ports   p2 ON l.targetPortId   = p2.id
WHERE (:status IS NULL OR l.status = :status)
```

#### 3.2.4 static 数据源模式

直接在 JSON 编辑器中填写响应体，适用于固定响应的接口（如认证、心跳等）：

```javascript
{
  dataSource: {
    type: "static",
    body: {
      "accessSession": "x-{{uuid}}",
      "roaRand": "{{random}}",
      "expires": 1800
    }
  }
}
```

支持内置占位符：`{{uuid}}`、`{{random}}`、`{{timestamp}}`、`{{date}}`。

### 3.3 HTTP 接口运行时架构

#### 3.3.1 请求处理管道

```
请求进入
  │
  ▼
┌──────────────────┐
│  RouteDispatcher  │  动态路由表，匹配 method + path
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  AuthMiddleware   │  根据接口 auth 配置校验 Token
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  FaultInjector    │  延迟注入、错误码注入
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  QueryPipeline    │  根据数据源类型分发处理
│                   │  sql: SQL引擎执行（参数绑定→count→分页→查询）
│                   │  static: 直接返回 JSON + 占位符替换
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ ResponseRenderer  │  模板渲染 + 字段映射
└──────────────────┘
```

#### 3.3.2 核心模块职责

| 模块 | 职责 |
|------|------|
| **RouteDispatcher** | 维护动态路由表，接口配置变更时实时更新路由注册 |
| **AuthMiddleware** | Token 颁发、验证、过期管理 |
| **FaultInjector** | 延迟、错误码、格式错误等异常注入 |

### 12.4 接口请求处理流程示例

**接口配置：**

```javascript
{
  id: "api_001",
  path: "/rest/openapi/network/v1/devices",
  method: "GET",
  auth: { type: "xtoken", headerName: "X-Auth-Token" },
  dataSource: {
    type: "sql",
    sql: `SELECT * FROM devices
          WHERE (:type IS NULL OR type = :type)
          ORDER BY name ASC`
  },
  query: {
    params: [{ param: "type", sqlParam: ":type", default: null }],
    pagination: { enabled: true, pageNoParam: "pageNo", pageSizeParam: "pageSize", defaultPageSize: 100 }
  },
  response: {
    template: { code: 0, data: "{{items}}", total: "{{total}}", pageNo: "{{pageNo}}", pageSize: "{{pageSize}}" }
  }
}
```

**请求处理：**

```
插件请求: GET /rest/openapi/network/v1/devices?type=switch&pageNo=2&pageSize=50
         Header: X-Auth-Token: x-yyyyyyy

1. RouteDispatcher
   → 匹配到 api_001 配置（GET + /rest/openapi/network/v1/devices）

2. AuthMiddleware
   → 从 Header 取 X-Auth-Token → 内存 tokenMap 验证有效 ✓

3. QueryPipeline (sql 模式)
   → 参数绑定: :type = 'switch'
   → count 查询: SELECT COUNT(*) FROM (SELECT * FROM devices WHERE type = 'switch') → total = 5000
   → 分页查询: SELECT * FROM devices WHERE type = 'switch' ORDER BY name ASC LIMIT 50 OFFSET 50
   → 返回第 51~100 条数据

4. ResponseRenderer
   → template 填充 {{items}}/{{total}}/{{pageNo}}/{{pageSize}}

响应:
{
  "code": 0,
  "data": [{ "name": "交换机-51", "dn": "NE=xxx", "type": "switch", ... }, ...],
  "total": 5000,
  "pageNo": 2,
  "pageSize": 50
}
```
