## 1. Executive Summary（执行摘要）

### 1.1 Problem Statement（问题陈述）

MindOps 采集纳管插件在开发与测试阶段依赖真实的 ManageOne / eSight 网管系统，但真实环境搭建成本高、占用资源大；同时真实环境中的设备种类、数据规模、异常场景有限，导致许多测试场景（如特定设备缺失、特定拓扑、异常响应、大规模数据）无法被有效覆盖和验证。

### 1.2 Proposed Solution（解决方案）

构建一个轻量、可自定义的**网管系统模拟工具**。通过图形化拓扑编辑自由构造测试数据，通过 Web 界面自定义对外 HTTP 接口的请求与响应（响应体支持结构化模板 + SQL 查询逻辑），从而让采集插件可脱离真实网管系统，按需复现任意测试场景。

### 1.3 Success Criteria（成功指标）

| KPI | 目标值 |
|-----|--------|
| **拓扑自定义能力** | 用户可 100% 自定义设备类型、属性字段、连线关系，无需研发介入 |
| **接口自定义能力** | 单个接口的请求方法、路由、请求头、请求参数、响应体结构、响应数据逻辑（SQL）均可由用户通过 Web 界面完成配置，无需重启服务 |
| **数据规模支撑** | 单个测试场景可承载 ≥ 3 万台设备及其端口、链路数据，分页查询响应时间 < 1 秒 |
| **测试场景复用** | 拓扑与接口配置可保存、导出、导入，测试场景可在团队内（≥ 10 人）复用 |
| **上手成本** | 测试工程师在无研发支持下，≤ 30 分钟可完成一个新测试场景（拓扑 + 接口）的搭建 |

## 2. User Experience & Functionality（用户体验与功能）

### 2.1 User Personas（用户画像）

| 画像 | 描述 | 规模 |
|------|------|------|
| **采集插件测试工程师**（主要） | 负责 MindOps 采集纳管插件的功能与场景测试，需要构造多样化的网管数据与接口行为来验证采集逻辑 | 约 10 人 |

本工具**不面向**：多租户用户、外部客户、运维人员、运营人员。

### 2.2 User Stories & Acceptance Criteria（用户故事与验收标准）

#### Story 1：自定义设备类型与拓扑

> 作为测试工程师，我希望可以自行定义任意设备类型并画出它们之间的连接关系，这样我就能构造真实网管中不存在但测试场景需要的拓扑数据。

**Acceptance Criteria：**
- 支持在 Web 界面新增、编辑、删除设备类型，包括图标、名称、可配置属性字段（字段名、类型、默认值）
- 支持在画布上通过拖拽方式放置设备、通过连线方式建立设备间关系
- 设备的关键标识（如 DN）支持按模板规则自动生成，用户可预览实际值
- 单设备可配置端口数量与命名规则，端口随设备自动生成
- 画布支持缩放、平移、多选、搜索定位、适应画布
- 一个拓扑场景可作为一份独立数据保存、命名、再次打开编辑

#### Story 2：自定义对外 HTTP 接口

> 作为测试工程师，我希望可以在 Web 界面自由定义一个 HTTP 接口的所有细节（方法、路由、参数、请求头、认证、响应体），这样就能精确模拟任意网管系统对外接口的行为。

**Acceptance Criteria：**
- 支持配置：请求方法（GET/POST/PUT/DELETE 等）、请求路由、查询参数、请求头、认证方式（无认证 / Token / Basic）
- 每个接口都具备独立的**启用开关**：关闭时该接口对外不可访问（返回 404 或可配置的错误），开关变更实时生效，无需重启
- 每个接口必须通过**拓扑绑定下拉框**选择一个已保存的拓扑场景作为数据来源：
  - 下拉框选项实时来自系统中已保存的拓扑场景列表
  - 未绑定拓扑的接口在 SQL 模式下不可保存 / 不可启用；静态模式可不绑定
  - 绑定关系决定 SQL 模式下虚拟表（设备 / 端口 / 链路）的数据范围
  - 支持切换绑定到其他拓扑场景，切换后立即以新场景数据响应请求
  - 被某接口绑定的拓扑场景在删除前需给出提示
- 支持配置响应体：内容类型、状态码、响应头、响应体结构模板
- 响应数据支持两种来源模式：
  - **静态模式**：用户直接填写固定 JSON 响应体，并可使用占位符（如 UUID、随机数、时间戳）
  - **SQL 模式**：用户编写 SQL 语句，基于绑定拓扑场景中的数据（设备 / 端口 / 链路）动态产生响应数据
- SQL 模式支持按 URL 请求参数自动绑定到 SQL 参数、支持分页、支持跨表关联（设备-端口-链路）
- 配置保存后立即生效，无需重启服务
- 提供"测试执行"功能，用户输入测试参数即可预览实际响应
- 接口可分组管理、导入 / 导出

#### Story 3：模拟认证流程

> 作为测试工程师，我希望能模拟网管系统的 Token 认证流程，以便测试采集插件的认证对接逻辑。

**Acceptance Criteria：**
- 支持配置 Token 颁发接口（请求/响应样式由用户自定义）
- 颁发出的 Token 可被后续接口校验，校验失败返回 401
- 支持配置 Token 有效期，过期自动失效
- 支持在管理界面手动使 Token 立即失效

#### Story 4：模拟异常场景

> 作为测试工程师，我希望可以人为注入延迟和错误响应，以便验证采集插件在异常条件下的鲁棒性。

**Acceptance Criteria：**
- 单个接口可配置固定响应延迟
- 单个接口可配置按概率返回指定错误状态码（如 400 / 401 / 403 / 404 / 500）
- 单个接口可临时暂停（全部请求返回预设错误或直接拒绝）

#### Story 5：场景持久化与复用

> 作为测试工程师，我希望我构造好的拓扑和接口配置可以保存下来并分享给同事，避免重复劳动。

**Acceptance Criteria：**
- 拓扑与接口配置均可命名保存
- 支持自动保存（避免因意外操作丢失数据）
- 支持拓扑历史版本查看与回退
- 支持以文件形式导出整套场景（拓扑 + 接口配置），并可在另一台设备导入还原

#### Story 6：可观测性

> 作为测试工程师，我希望能看到采集插件对模拟工具发出的请求记录，便于定位联调问题。

**Acceptance Criteria：**
- 记录每次请求的时间、来源、方法、路由、参数、状态码、耗时
- 提供仪表盘查看服务状态、数据规模统计、最近请求
- 支持按模块 / 级别筛选日志

### 2.3 Non-Goals（非目标，本版本明确不做）

- 多用户、多租户、登录注册、角色权限体系
- 告警模拟（告警数据、告警推送）
- 性能指标模拟（KPI 采集、时序指标）
- SNMP / SFTP / Kafka 协议的模拟
- 面向生产环境的高并发、高可用部署
- 真实网管厂商协议的完整一致性（只需满足采集插件测试所需的行为）

## 4. Technical Specifications（技术规格 — 仅业务层约束）

> 本 PRD 仅描述业务层约束与集成点，**不涉及架构设计、技术选型、数据库表结构及代码实现**，相关设计将在后续技术设计文档中定义。

### 4.1 Integration Points（集成点）

| 集成对象 | 集成内容 |
|----------|----------|
| **MindOps 采集纳管插件** | 作为 HTTP 客户端消费本工具暴露的接口；本工具仅需在行为上满足其采集语义 |
| **真实网管接口规范**（ManageOne / eSight） | 提供接口路由、参数、响应结构的参考蓝本，用户按此在本工具中复刻 |

### 4.2 Security & Privacy（安全与隐私）

- 使用范围限定在个人开发 / 测试网络，不处理真实生产数据、不包含真实用户隐私信息
- 拓扑数据、接口配置本地存储，不上传任何外部系统
- 认证仅为行为模拟（供采集插件联调），不作为真实安全机制使用

### 4.3 Constraints & Assumptions（约束与假设）

| 项 | 说明 |
|----|------|
| **使用规模** | 单用户使用，无高并发诉求 |
| **网络环境** | 采集插件与本工具处于同一可达网络 |
| **数据规模** | 单场景设备数 ≥ 3 万，配套推荐内存 8GB+ |
| **浏览器** | 仅保证在 Chrome、Firefox、Edge 最新版下可用 |

## 5. Risks & Roadmap（风险与路线图）

### 5.1 Phased Rollout（分阶段交付）

无严格截止日期，按里程碑推进。

| 里程碑 | 交付主题 | 范围 |
|--------|----------|------|
| **M1（MVP 基础）** | 拓扑自定义能力 | 设备类型自定义、拓扑画布编辑、端口自动生成、连线关系、画布操作 |
| **M2（MVP 核心）** | 接口自定义能力 | HTTP 接口自定义（方法 / 路由 / 参数 / 请求头 / 响应体）、SQL 与静态两种响应模式、Token 认证模拟、异常注入、拓扑与接口的保存 / 历史 / 导入导出 |
| **M4（体验完善）** | 可观测性与易用性 | 仪表盘、数据查看、请求日志、系统设置 |
| **后续规划（未排期）** | 扩展协议与观测维度 | SNMP、SFTP、Kafka、告警模拟、性能指标模拟 |

### 5.2 需求优先级

| 优先级 | 功能 | 里程碑 |
|--------|------|--------|
| P0 | 自定义设备类型与属性 | M1 |
| P0 | 拓扑画布与连线编辑 | M1 |
| P0 | 端口自动生成与编辑 | M1 |
| P0 | HTTP 接口自定义（请求 / 响应 / 认证） | M2 |
| P0 | SQL 驱动的响应数据逻辑 | M2 |
| P0 | Token 认证模拟 | M2 |
| P0 | 拓扑与接口持久化 | M2 |
| P1 | 异常注入（延迟 / 错误码 / 暂停） | M2 |
| P1 | 拓扑历史版本 | M2 |
| P1 | 导入 / 导出 | M2 |
| P1 | 仪表盘 / 数据查看 / 请求日志 | M4 |
| P2 | 系统设置 | M4 |
| 后续 | SNMP / SFTP / Kafka / 告警 / 指标 | 未排期 |

### 5.3 Technical Risks（产品层风险）

| 风险 | 描述 | 缓解 |
|------|------|------|
| **SQL 灵活性 vs 易用性** | 测试工程师 SQL 水平参差，过度依赖 SQL 可能抬高上手成本 | 为设备 / 端口 / 链路各自提供默认 SQL 模板，用户可在模板基础上修改 |
| **大规模数据性能** | 3 万设备场景下查询响应可能变慢 | 明确性能目标（分页查询 < 1 秒）并作为验收标准 |
| **数据丢失** | 拓扑编辑在内存中进行，异常退出可能丢失 | 提供自动保存、定时保存、历史版本与退出前提示 |
| **接口真实度偏差** | 用户自定义的接口可能与真实网管存在细微差异，导致采集插件在真实环境再次失败 | 在接口配置模板中沉淀 ManageOne / eSight 的常用接口预置；提供导入导出以便团队共享已校准的场景 |
| **场景碎片化** | 10 人团队各自构造场景可能重复 | 通过导出 / 导入机制支持场景共享与复用 |

## 6. 已确认事项（补充需求细则）

| 项 | 决议 |
|----|------|
| **ManageOne / eSight 接口预置** | 本版本不内置接口模板，接口完全由用户按需自定义（后续如整理出标准接口清单再评估是否内置） |
| **自动保存间隔** | 默认 60 秒 |
| **历史版本保留数量** | 默认 3 个（超出按时间最早者淘汰） |
| **多拓扑并行编辑** | 需要支持。用户可同时打开多个拓扑场景进行编辑，彼此互不干扰 |
| **导出文件安全** | 导出的场景文件**不**要求加密或签名，以纯文本文件形式便于团队共享 |

对应影响：
- Story 1 的验收标准补充：支持同时打开多个拓扑场景，每个场景独立维护编辑状态与未保存标记
- Story 5 的验收标准补充：自动保存默认间隔 60 秒；历史版本默认保留最近 3 个；导出文件为明文结构，可直接查看与编辑
