# 类型管理：搜索 / 批量导出 / 分类筛选 - 开发方案

## 概述

为类型管理页面（`TypesView` → `NodeTypeTable` / `EdgeTypeTable`）新增三个功能：

| 功能 | 节点类型 | 边类型 | 说明 |
|------|:---:|:---:|------|
| 页面关键词搜索 | ✓ | ✓ | 按 code / name / description 模糊匹配 |
| 批量导出 | ✓ | ✓ | 导出选中行（或全部），JSON 格式下载 |
| 分类列筛选 | ✓ | - | 边类型无 category 字段，此项仅节点类型适用 |

---

## 当前状态分析

### 后端 API 现状

```python
# 当前——零查询参数，全量返回
@router.get("/node-types")
def list_node_types() -> dict:       # 无 Query 参数
    ... "SELECT * FROM node_types ORDER BY category, name"
```

- API 设计文档已标注 `GET /admin/api/node-types` "可按 `category` 过滤"——**未实现**
- 无搜索（keyword）参数、无分页

### 前端现状

- 表格数据源直接使用 `nodeTypes` / `edgeTypes` 响应式数组（全量渲染，前端分页仅靠 Ant Design `pagination` prop 做内存分页）
- 已有机能：行选择（`selectedRowKeys`）、批量删除
- 未安装任何文件下载库（如 `file-saver`）

### 已有可参考模式

- `POST /admin/api/apis/export`（API 配置导出）：body 传 `{ "ids": [...] }`，不传则全部
- 前端示例 `apiPost('/apis/export', { ids })` 获取 JSON → 前端触发浏览器下载

---

## 方案设计

### 决策：搜索与筛选用前端还是后端？

类型数据量小（典型 < 100 条），全量数据已在内存中，**全部用前端实现**，无需新增后端查询参数：

- **搜索**：computed 过滤，输入框 onChange 即时响应
- **分类筛选**：Ant Design Table 内置 `column.filters` 属性
- **批量导出**：仅需新增后端导出端点（JSON 下载），前端按钮触发

优点：
- 零后端改动（除导出端点外），改动面最小
- 无网络延迟，体验即时
- 避免维护前后端双份搜索/筛选逻辑

## 1. 功能一：页面搜索

### 1.1 搜索范围

| 类型 | 搜索字段 |
|------|---------|
| 节点类型 | `code`、`name`、`description`、`category` |
| 边类型 | `code`、`name`、`description` |

### 1.2 前端实现（以节点类型为例）

```typescript
// NodeTypeTable.vue
const searchText = ref('')

const filteredNodeTypes = computed(() => {
  const kw = searchText.value.trim().toLowerCase()
  if (!kw) return nodeTypes.value
  return nodeTypes.value.filter(nt =>
    nt.code.toLowerCase().includes(kw) ||
    nt.name.toLowerCase().includes(kw) ||
    (nt.description ?? '').toLowerCase().includes(kw) ||
    nt.category.toLowerCase().includes(kw)
  )
})
```

- 工具栏新增 `a-input-search` 组件，带 `v-model:value="searchText"`
- 输入 300ms debounce 后更新（Ant Design `a-input-search` 自带回车/点击搜索触发，即时过滤场景可改用 `@input` + debounce）
- 表格 `dataSource` 从 `nodeTypes` 改为 `filteredNodeTypes`
- 清空搜索词时恢复全量

**边类型同理**，搜索范围去掉 `category`。

### 1.3 UI 布局

工具栏变为三行式布局：

```
[标题]          [a-input-search]  [批量删除] [批量导出] [新建]
```

搜索框宽度约 240px，与右侧按钮组用 `a-space` 分隔。

## 2. 功能二：批量导出

### 2.1 后端：新增导出端点

**节点类型导出**：

```
POST /admin/api/node-types/export
```

**边类型导出**：

```
POST /admin/api/edge-types/export
```

**请求体**：

```json
{ "ids": ["nt_switch", "ntype_abc123"] }
```

- `ids` 为空或不传 → 导出全部
- `ids` 传入 → 仅导出指定的类型

**响应**：`Content-Type: application/json`，`Content-Disposition: attachment; filename="node-types-export.json"`

响应体即 `{ code: 0, data: { items: NodeTypeDetail[] }, message: "ok" }`，`items` 中每条包含完整的 `fields` 嵌套数组。

### 2.2 前端：下载触发

```
┌──────────────────────────────────────────┐
│ 工具栏                                      │
│ [标题]  [🔍 搜索]  [批量删除] [批量导出] [新建] │
└──────────────────────────────────────────┘
```

**交互逻辑**：

1. 点击"批量导出"按钮
2. 若 `selectedRowKeys` 非空 → 导出选中行；否则 → 导出当前搜索/筛选后的可见行
3. 调用 `apiPost('/node-types/export', { ids })` 获取 JSON
4. 构造 `Blob` + `URL.createObjectURL` + 隐藏 `<a>` 触发下载
5. 文件名：`node-types-export-20260504T120000.json`（带时间戳）

**按钮状态**：
- 始终可点击（有数据时可导出全部）
- 选中行时按钮文案可改为"导出选中 (N)"以强化暗示

### 2.3 前端 API 层

```typescript
// types.ts  nodeTypeApi / edgeTypeApi 各新增：
export: (ids?: string[]): Promise<{ items: NodeTypeDetail[] }> =>
  apiPost('/node-types/export', { ids }),

// 通用下载工具函数（新增 utils/download.ts）
export function downloadJson(data: unknown, filename: string) {
  const blob = new Blob([JSON.stringify(data, null, 2)], { type: 'application/json' })
  const url = URL.createObjectURL(blob)
  const a = document.createElement('a')
  a.href = url
  a.download = filename
  a.click()
  URL.revokeObjectURL(url)
}
```

> 无需安装 `file-saver` 等第三方依赖，`Blob` + `URL.createObjectURL` 已覆盖需求。

## 3. 功能三：分类列筛选

### 3.1 适用范围

- **节点类型**：`category` 列（Ant Design `a-table-column` 内置 `filters` props）
- **边类型**：无 `category` 字段，不适用此功能

### 3.2 实现

利用 Ant Design Table 内置的列筛选：

```html
<a-table-column title="分类" dataIndex="category" width="100">
  <template #default="{ text }">
    <a-tag>{{ text }}</a-tag>
  </template>
</a-table-column>
```

改为：

```html
<a-table-column
  title="分类"
  dataIndex="category"
  width="100"
  :filters="categoryFilters"
  :filterMultiple="true"
  @filter="(value: string[], record: NodeTypeDetail) => value.includes(record.category)"
>
  <template #default="{ text }">
    <a-tag>{{ text }}</a-tag>
  </template>
</a-table-column>
```

其中 `categoryFilters` 由数据动态生成：

```typescript
const categoryFilters = computed(() => {
  const cats = [...new Set(nodeTypes.value.map(nt => nt.category))]
  return cats.map(c => ({ text: c, value: c }))
})
```

> 注意：`@filter` 是 Ant Design Vue 4.x 的写法（`onFilter` 的别名）。具体 API 依据实际版本调整——`v4.2` 中使用 `:filters` + `:onFilter`。

### 3.3 与搜索联动

- 搜索框和列筛选独立生效，叠加过滤（搜索 → computed 过滤；列筛选 → Ant Design Table 内置过滤）
- 顺序：先列筛选（Table 内置），再搜索（computed）——更好的方式是将搜索也并入 computed，统一数据源，避免与 Table 内置 filter 冲突

**推荐方案**：搜索和分类筛选均在 computed 中完成，Table 不使用内置 `filters`，改为在分类列头部加一个 `a-select` 下拉（或直接用 `a-table` 的 `filters` 但数据源用 computed 预处理）。实际推荐——

将 `filteredNodeTypes` computed 同时覆盖搜索 + 分类筛选：

```typescript
const filteredNodeTypes = computed(() => {
  let list = nodeTypes.value
  const kw = searchText.value.trim().toLowerCase()
  if (kw) {
    list = list.filter(nt => /* match code/name/desc/category */)
  }
  if (categoryFilter.value.length > 0) {
    list = list.filter(nt => categoryFilter.value.includes(nt.category))
  }
  return list
})
```

分类筛选 UI 改用工具栏中的 `a-select` 多选下拉（mode="multiple"），与搜索框并排放置。这样避免与 Table 内置 filter 的状态管理冲突。
