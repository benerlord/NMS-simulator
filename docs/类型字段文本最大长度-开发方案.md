# 类型字段文本最大长度 - 开发方案

## 概述

类型管理界面中，新增节点/边类型属性时，属性类型为"文本 (text)"时无法设置最大长度限制。本方案分两阶段：

**阶段一（已完成）：字段定义** — 为 `node_type_fields` 和 `edge_type_fields` 表新增 `max_length` 列，在类型管理界面中可配置，前后端校验：文本类型必填且 >= 1，非文本类型自动忽略。

**阶段二（已完成）：运行时校验** — 在画布上创建/编辑节点或边时，对文本类型字段的实际值进行长度校验，超长则拒绝保存。覆盖后端 `set_node_attrs` / `set_edge_attrs` 接口和前端 `NodeAttrsPanel` / `NodeAttrsModal` / `EdgeAttrsPanel` 输入控件。

## 1. 数据库

### 1.1 新增列（`migrations.py`）

沿用项目现有的 idempotent ALTER TABLE 模式（try/except `sqlite3.OperationalError`）：

```python
try:
    conn.execute("ALTER TABLE node_type_fields ADD COLUMN max_length INTEGER")
except sqlite3.OperationalError:
    pass

try:
    conn.execute("ALTER TABLE edge_type_fields ADD COLUMN max_length INTEGER")
except sqlite3.OperationalError:
    pass
```

- `INTEGER` 类型，可空
- 现有行的 `max_length` 为 NULL，保持向后兼容
- `seed.py` 无需改动

## 2. 后端

### 2.1 Pydantic Schema（`schemas/node_type.py`）

**新增字段：** `max_length: Optional[int] = Field(default=None, ge=1)`

6 个类各插入该字段：`NodeTypeFieldCreate`, `NodeTypeFieldUpdate`, `NodeTypeFieldItem`, `EdgeTypeFieldCreate`, `EdgeTypeFieldUpdate`, `EdgeTypeFieldItem`。

**条件校验（model_validator）：**

```python
@model_validator(mode='after')
def validate_max_length_for_text(self):
    if self.field_type != 'text':
        return self
    if self.max_length is None:
        raise ValueError('文本类型必须设置 max_length')
    if self.max_length < 1:
        raise ValueError('max_length 必须 >= 1')
    return self
```

- `Create` validator：`field_type` 必填，直接判断 `!= 'text'`
- `Update` validator：`field_type` 可选，判断 `is None or != 'text'` 避免更新非 field_type 属性时误触发

### 2.2 路由（`node_type.py`）

- `_get_node_type_fields` / `_get_edge_type_fields`：`NodeTypeFieldItem(...)` 构造中新增 `max_length=r["max_length"]`
- `create_node_type_field` / `create_edge_type_field`：INSERT 列名和 VALUES 各加 `max_length`
- `update_node_type_field` / `update_edge_type_field`：无需改动（动态 SET 子句自动包含）

## 5. 运行时校验（阶段二 待开发）

类型管理中定义了文本字段的 `max_length` 后，在画布上创建/编辑节点（或边）时，需要校验输入的字段值是否超过长度限制。校验在前后端同时执行。

### 5.1 数据结构回顾

```
node_type_fields.max_length (定义层)
        ↓
node_attrs.value (实例层)
```

- `node_type_fields` 存储字段定义（含 `max_length`、`required` 等元数据）
- `node_attrs` 存储每个节点实例的实际字段值（`node_id`, `field_key`, `value`）
- 当前 `set_node_attrs` 只校验了 `required`（必填字段是否存在），**未校验 `max_length`**
- 边类型同理（`edge_type_fields` → `edge_attrs`，`set_edge_attrs`）

### 5.2 后端 — `set_node_attrs`（`node.py` line 306-347）

**现状：** 在必填字段校验（line 318-333）之后，直接 DELETE + INSERT attrs，未对 value 做长度校验。

**改造方案：** 在必填字段校验通过后、写数据库之前，增加 max_length 校验逻辑：

1. 查询 `node_type_fields` 获取所有定义了 `max_length` 且 `field_type='text'` 的字段及其 `max_length` 值
2. 遍历提交的 `attrs`，对每个 `field_key` 在第一步结果中查找
3. 若 `field_key` 有 `max_length` 限制，且 `len(value or "") > max_length`，则返回 400 错误，告知哪个字段超长及限制值

**伪代码：**

```python
# 在 required_fields 校验通过后、transaction 之前插入

# 查询该节点类型下所有定义了 max_length 的文本字段
max_len_rows = conn.execute(
    "SELECT field_key, field_label, max_length FROM node_type_fields "
    "WHERE node_type_id = ? AND field_type = 'text' AND max_length IS NOT NULL",
    (node_row["node_type_id"],),
).fetchall()

max_len_map = {r["field_key"]: (r["field_label"], r["max_length"]) for r in max_len_rows}

# 校验每个提交的属性值
for attr in attrs:
    if attr.field_key in max_len_map and attr.value:
        label, limit = max_len_map[attr.field_key]
        if len(attr.value) > limit:
            raise HTTPException(
                status_code=400,
                detail={
                    "code": 40407,
                    "message": f"字段「{label}」内容长度不能超过 {limit} 个字符",
                },
            )
```

**关键设计决策：**

- `attr.value` 为 `None` 或空字符串时不校验（允许留空，仅校验非空值）
- 只对有 `max_length` 定义的 `text` 类型字段做校验
- 字段类型已在定义层校验为 `text`，此处不再重复校验 `field_type`
- 错误码 `40407` 需确保不与现有错误码冲突

### 5.3 后端 — `set_edge_attrs`（`edge.py` line 302-343）

同上，在必填字段校验后、事务写入前插入相同的校验逻辑，查询 `edge_type_fields` 表替代 `node_type_fields`。

### 5.4 前端 — `NodeAttrsPanel.vue`

**文件:** `frontend/src/components/canvas/NodeAttrsPanel.vue`

文本类型字段的 `<Input>` 组件需绑定 `:maxlength` 属性，由浏览器在输入层面阻止超长输入：

```html
<a-input
  v-model:value="formData[field.fieldKey]"
  :maxlength="field.maxLength || undefined"
  :placeholder="field.defaultValue || ''"
/>
```

- `:maxlength` 为 `undefined`（即 `null || undefined`）时，HTML input 不限制长度
- 后端校验作为兜底，防止绕过前端直接调 API

### 5.5 前端 — `NodeAttrsModal.vue`

**文件:** `frontend/src/components/canvas/NodeAttrsModal.vue`

与 5.4 完全相同的改造，文本 `<Input>` 绑定 `:maxlength="field.maxLength || undefined"`。

### 5.6 前端 — `EdgeAttrsPanel.vue`

**文件:** `frontend/src/components/canvas/EdgeAttrsPanel.vue`

与 5.4 完全相同的改造，文本 `<Input>` 绑定 `:maxlength="field.maxLength || undefined"`。

### 5.7 优化 — Input 字符计数显示（阶段三 已完成）

**现状问题：** 阶段二已通过 `:maxlength` 在浏览器层面阻止超长输入，但用户**看不到**：
- 该字段的最大长度是多少
- 当前已输入了多少字符
- 剩余可输入多少字符

输入到上限时，键盘输入被静默吞掉，用户不知道是被限制了还是输入框坏了。

**改造方案：** Ant Design Vue 的 `<Input>` 组件原生支持 `showCount` 属性，启用后会在输入框下方显示 `已输入字符数 / 最大长度` 的计数提示。

```html
<!-- 当前（阶段二） -->
<Input
  :value="getFieldValue(field.fieldKey)"
  @input="(e: any) => setFieldValue(field.fieldKey, e.target.value)"
  :maxlength="field.maxLength || undefined"
/>

<!-- 优化后（阶段三） -->
<Input
  :value="getFieldValue(field.fieldKey)"
  @input="(e: any) => setFieldValue(field.fieldKey, e.target.value)"
  :maxlength="field.maxLength || undefined"
  :showCount="!!field.maxLength"
/>
```

**效果：**

| maxLength | 输入框表现 |
|-----------|-----------|
| 255 | 超出 255 字符阻止输入 + 右下角显示 `128 / 255` |
| null | 无限制，不显示计数 |

**涉及文件（3 个）：**

| 文件 | 改动 |
|------|------|
| `frontend/src/components/canvas/NodeAttrsPanel.vue` | text `<Input>` 新增 `:showCount="!!field.maxLength"` |
| `frontend/src/components/canvas/NodeAttrsModal.vue` | 同上 |
| `frontend/src/components/canvas/EdgeAttrsPanel.vue` | 同上 |

**关键设计决策：**

- `showCount` 只在 `field.maxLength` 有值时启用（`!!field.maxLength`），否则不显示计数
- 不需要 `maxlength` prop 也能单独显示 `showCount`，但两者并存效果最好——`maxlength` 阻止输入，`showCount` 告知原因
- 如果 `value` 为 null 或空字符串，计数显示 `0 / 255`
- `<InputNumber>` 不适用（只用于数字类型字段，无长度限制需求）
