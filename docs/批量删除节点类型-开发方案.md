# 批量删除类型 - 开发方案

## 概述

当前类型管理页面（`TypesView` → `NodeTypeTable` / `EdgeTypeTable`）仅支持逐行删除类型。本方案为节点类型和边类型统一新增批量勾选 + 一键删除功能，同时覆盖前端 UI、API 层、后端接口。

---

## 涉及文件

| 层 | 文件 | 改动类型 |
|---|---|---|
| 后端 Schema | `backend/app/admin/schemas/node_type.py` | 新增 `NodeTypeBatchDelete` + `EdgeTypeBatchDelete` |
| 后端路由 | `backend/app/admin/node_type.py` | 新增 2 个批量删除端点 |
| 前端 API 层 | `frontend/src/api/types.ts` | 新增 `BatchDeleteResult` 类型 + 2 个接口函数 |
| 前端 Composable | `frontend/src/composables/useTypes.ts` | 新增 `deleteNodeTypes` + `deleteEdgeTypes` |
| 前端组件 | `frontend/src/components/types/NodeTypeTable.vue` | UI 改造（复选框 + 批量删除按钮） |
| 前端组件 | `frontend/src/components/types/EdgeTypeTable.vue` | UI 改造（复选框 + 批量删除按钮） |

## 1. 后端

### 1.1 新增 Schema（`schemas/node_type.py`）

```python
class NodeTypeBatchDelete(BaseModel):
    ids: list[str] = Field(..., min_length=1, max_length=200)


class EdgeTypeBatchDelete(BaseModel):
    ids: list[str] = Field(..., min_length=1, max_length=200)
```

- `min_length=1`：不允许空数组
- `max_length=200`：防止单次请求过大

### 1.2 新增端点（`node_type.py`）

**节点类型批量删除**：

```
POST /admin/api/node-types/batch-delete
```

**边类型批量删除**：

```
POST /admin/api/edge-types/batch-delete
```

请求体均为 `{ "ids": ["xxx", "yyy"] }`。

**处理逻辑**（两边端点一致）：

1. 遍历传入的 `ids`，逐条检查是否存在
2. 对每个存在的类型，检查是否被实例表引用（nodes 的 `node_type_id` / edges 的 `edge_type_id`）
3. 被引用的类型：跳过删除，计入 `skipped` 列表并附带原因
4. 未被引用的类型：级联删除其 fields 子表，再删除主表行
5. 整个操作在**一个事务**中完成

**响应体**：

```json
{
  "code": 0,
  "data": {
    "deletedCount": 2,
    "skipped": [
      { "id": "ntype_xyz", "reason": "该类型已被节点使用，无法删除" }
    ]
  },
  "message": "ok"
}
```

### 1.3 路由顺序注意事项

批量端点（`/node-types/batch-delete`、`/edge-types/batch-delete`）**必须注册在**参数化单删端点（`/{type_id}`）**之前**，否则 FastAPI 会将 URL 中的 `batch-delete` 匹配为 `type_id`。

## 2. 前端 API 层

### 2.1 `types.ts` — 新增类型与函数

```typescript
export interface BatchDeleteResult {
  deletedCount: number
  skipped: { id: string; reason: string }[]
}

// nodeTypeApi 新增：
batchDelete: (ids: string[]): Promise<BatchDeleteResult> =>
  apiPost('/node-types/batch-delete', { ids }),

// edgeTypeApi 新增：
batchDelete: (ids: string[]): Promise<BatchDeleteResult> =>
  apiPost('/edge-types/batch-delete', { ids }),
```

> 注意：`apiDelete` 不支持 request body，因此使用 `apiPost` + 语义化路径 `/batch-delete`。

### 2.2 `useTypes.ts` — 新增方法

```typescript
// useNodeTypes() 新增：
async function deleteNodeTypes(ids: string[]) { ... }

// useEdgeTypes() 新增：
async function deleteEdgeTypes(ids: string[]) { ... }
```

## 3. 前端 UI

节点类型（`NodeTypeTable.vue`）和边类型（`EdgeTypeTable.vue`）改造模式完全一致：

### 3.1 新增功能

- **行选择**：`a-table` 增加 `rowSelection` 配置（复选框列）
- **批量删除按钮**：工具栏新增"批量删除"按钮，选中行数 > 0 时可点击
- **确认弹窗**：点击批量删除后弹出 `a-popconfirm`，提示"确定删除选中的 N 个节点/边类型？"

### 3.2 模板改动（以边类型为例）

```html
<a-table
  :rowSelection="{ selectedRowKeys, onChange: (keys: string[]) => { selectedRowKeys = keys } }"
  ...
/>

<div class="table-toolbar">
  <span class="toolbar-title">边类型</span>
  <a-space>
    <a-popconfirm
      :title="`确定删除选中的 ${selectedRowKeys.length} 个边类型？`"
      :disabled="selectedRowKeys.length === 0"
      @confirm="handleBatchDelete"
    >
      <a-button :disabled="selectedRowKeys.length === 0" danger>
        批量删除
      </a-button>
    </a-popconfirm>
    <a-button type="primary" @click="openCreate">新建边类型</a-button>
  </a-space>
</div>
```

### 3.3 批量删除回调

```typescript
const selectedRowKeys = ref<string[]>([])

async function handleBatchDelete() {
  if (selectedRowKeys.value.length === 0) return
  try {
    const result = await deleteEdgeTypes(selectedRowKeys.value)
    if (result.skipped.length > 0) {
      message.warning(`部分类型未能删除: ...`)
    } else {
      message.success(`成功删除 ${result.deletedCount} 个边类型`)
    }
    selectedRowKeys.value = []
  } catch {}
}
```

---

## 4. 交互细节

1. 仅已加载的列表中可被勾选；跨页勾选由 Ant Design `rowSelection` 自动跟踪（`rowKey="id"`）
2. 批量删除完成后：清空选中状态、刷新列表
3. 被 `skipped` 的类型在提示中逐个列出原因，用户可据此处理（如先解绑关联节点）
4. 按钮在无选中项时 `disabled`
