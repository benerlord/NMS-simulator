# 开发问题记录

## 问题 1：接口管理页面出现两个重复搜索框

### 发现时间
2026-05-31

### 现象
接口管理页面存在两个功能重复的搜索框：
1. 工具栏中的"按路径搜索"（触发后端 API 过滤）
2. 工具栏下方的"输入关键字过滤接口（名称/路径）…"（客户端即时过滤）

### 定位分析

**根因**：迭代增量叠加，而非替换整合。

| 阶段 | 操作 | 结果 |
|------|------|------|
| 原始代码 | `ApiConfigTable.vue` 工具栏自带"按路径搜索"输入框 | 后端过滤，原有功能 |
| T3-1~T3-2 | 实现目录式分组视图 | 保留原工具栏不动，下方改为目录视图 |
| T3-3 | 实现搜索跨目录过滤 | **新增**一个独立搜索框在工具栏下方，未替换旧搜索框 |

T3-3 需要的是客户端即时过滤（不触发后端请求、自动展开匹配目录、折叠空目录），功能上覆盖了旧搜索框。但实现时选择了"追加"而非"替换"，导致两个搜索框并存。

### 解决方案

合并为一个统一搜索框，置于工具栏中：

- 移除工具栏的"按路径搜索"（后端过滤 `path` 参数）
- 移除独立的"输入关键字过滤接口…"搜索栏
- 工具栏改为统一的 **"搜索接口名称或路径…"** 输入框，纯客户端过滤（按名称 + 路径匹配），即时响应
- 相关代码清理：`pathInput` ref、`applyFilters`/`resetFilters` 中的 path 逻辑、`useApiConfigs` 中的 `path` 过滤

### 教训

- 新增功能覆盖旧功能时，应直接替换而非追加
- 实现前先审视现有代码是否与新需求重叠，避免 UI 冗余

## 问题 2：TypePalette 搜索框输入后变窄无法使用

### 发现时间
2026-05-27

### 现象
画布左侧面板 TypePalette 的 AutoComplete 搜索框中输入文字后，输入框变窄，无法展示内容。

### 定位分析

**根因**：AutoComplete 组件未设宽度。
- `.type-palette` 宽度仅 200px
- AutoComplete 未声明 `style="width: 100%"`，默认内容撑开宽度
- 下拉选项 label 过长（`名称 编码 分类` 三段拼接），溢出

### 解决方案
- AutoComplete 加 `:style="{ width: '100%' }"` 填满面板宽度
- 下拉选项 label 简化为 `名称 — 编码`
- 下拉面板设 `:dropdown-style="{ minWidth: '220px' }"` 独立撑开

## 问题 3：路由冲突导致批量域名端点 422

### 发现时间
2026-05-26

### 现象
`PUT /node-types/domains` 批量关联域端点返回"无更新字段"错误。

### 定位分析

**根因**：FastAPI 路由按注册顺序匹配。
- `PUT /node-types/{type_id}` 在 `PUT /node-types/domains` 之前注册
- 请求 `PUT /node-types/domains` 时，`domains` 被当作 `{type_id}` 捕获
- 命中 `update_node_type` 函数，`model_dump(exclude_unset=True)` 返回空字典 → "无更新字段"

### 解决方案
- 将批量域名端点移到 `{type_id}` 端点之前注册

## 问题 4：拓扑更新 domainId: null 无法清空域

### 发现时间
2026-05-26

### 现象
`PUT /topologies/{id}` 传 `{"domainId": null}` 试图清空域时报"无更新字段"。

### 定位分析

**根因**：Pydantic `model_dump(exclude_unset=True)` 行为。
- `TopologyUpdate.domain_id: Optional[str] = Field(default=None)`
- 用户传 `null` → Pydantic 解析为 `None`（等于默认值）
- `exclude_unset=True` 排除该字段
- 业务代码检查 `if body.domain_id is not None` 为 False，跳过

### 解决方案
- 改用 `"domain_id" in body.model_fields_set` 判断是否显式传入
- 显式传入 `None` 时也执行更新（允许清空域）

## 问题 5：删除节点类型时未检查 node_groups FK

### 发现时间
2026-05-26

### 现象
批量删除节点类型时报 `FOREIGN KEY constraint failed` 500。

### 定位分析

**根因**：删除前只检查了 `nodes` 表的 FK 引用，遗漏了 `node_groups` 表。
- `nodes.node_type_id` → 有检查
- `node_groups.node_type_id` → 未检查

### 解决方案
- 批量删除和单个删除均增加 `node_groups` 表的 FK 引用检查
- 被引用时跳过并提示"该类型已被节点组使用"

## 问题 6：导入 Excel 时字段类型非法值导致 500

### 发现时间
2026-05-25

### 现象
导入 Excel 时报 `CHECK constraint failed: field_type IN ('text','number','select','boolean')` 500。

### 定位分析

**根因**：Excel 字段 Sheet 的"字段类型"列直接传入数据库，未做校验。
- 空值、大写 `Text`、非法值 `string` 等直接触发 CHECK 约束

### 解决方案
- 插入前校验 `ftype`：`str().strip().lower()` 规范化 + 白名单校验
- 非法值时记录明确错误（含类型编码、字段标识、原始值），而非 500
