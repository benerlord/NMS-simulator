## 2. 关键技术实现方案

### 2.1 动态路由注册（mock 子应用）

- **方案**：FastAPI 启动时加载 `api_configs` 全表，为每条 `enabled=1` 的记录调用 `app.add_api_route`；运行时增删改通过 `RouteRegistry` 维护 `app.router.routes` 列表。
- **路径策略**：完整路径 = `settings.mock_path_prefix + api_configs.path`；`mock_path_prefix` 默认空串 → 接口直接挂在根路径上（如 `GET /rest/openapi/network/v1/devices`），便于复刻原系统 URL；如需统一前缀改成 `/mock` 等任意值。
- **关键点**：path 参数（`/devices/{id}`）用 FastAPI 原生占位；method/path 变更走"卸载旧 + 注册新"；enable 开关不动路由，在管道 [2] 步 404。
- **验收**：新增接口后 < 200ms 可被 `curl <api_configs.path>` 命中；禁用后立即返回 404；method 变更后旧 method 返回 405。

### 2.2 动态 CTE 视图生成（SQL 模式）

- **输入**：绑定拓扑 id + 用户 SQL。
- **流程**：
  1. 查询该拓扑下出现的所有 `node_type_id` 与 `edge_type_id`
  2. 为每个类型生成一个 `WITH <code> AS (SELECT 固定列 + 属性打平 FROM nodes JOIN node_attrs ...)` CTE
  3. 始终附加 `nodes / edges / children` 三个通用 CTE
  4. 拼接 `WITH ...所有 CTE... <用户 SQL>`
- **验收**：用户写 `SELECT * FROM switches WHERE vendor='华为'` 能直接返回；自定义属性字段自动出现在对应视图列中；绑定拓扑切换后视图列随之变化。

### 2.3 SQL 白名单校验

- **规则**：去除首部 `--` / `/* */` 注释与空白后，首关键字必须是 `SELECT` 或 `WITH`（大小写不敏感）。
- **实现**：`app/core/sql_executor.py::validate_readonly(sql) -> None | raise`
- **验收**：`INSERT` / `UPDATE` / `DELETE` / `DROP` / `ATTACH` / `PRAGMA` 全部拒绝并返回 40301；多语句（含 `;`）拒绝。

### 2.4 参数绑定与自动分页

- URL query 参数 → 按配置 `param_mapping` 映射为命名参数 `:paramName`
- 分页：`SELECT COUNT(*) FROM (<用户 SQL>) _t` 得 total；再 `<用户 SQL> LIMIT :pageSize OFFSET :offset` 取页
- **验收**：`?page=2&pageSize=20` 生效；total 正确；缺失参数用配置默认值；类型转换失败返回 40302。

### 2.5 响应模板渲染

- 基础占位符：`{{items}}` / `{{total}}` / `{{page}}` / `{{pageNo}}`（page 别名）/ `{{pageSize}}` / `{{uuid}}` / `{{now}}`
- 派生分页占位符（M6 LEGACY-05 Phase 1 新增）：`{{totalPageNo}}` / `{{totalPages}}`（前者别名）/ `{{hasNext}}` / `{{hasPrev}}` / `{{offset}}` / `{{count}}`
- 表达式占位符（M6 LEGACY-05 Phase 2 新增）：`{{<expr>}}` 支持算术 + 函数白名单 `ceil/floor/round/abs/min/max/int`，详见 §2.12
- 实现：简单字符串替换 + `json.loads` 验证结构，不引入 Jinja（避免过度工程）；表达式用 `ast.parse` + 节点白名单遍历求值，不用 `eval`
- **验收**：模板非法 JSON 返回 40303；`{{items}}` 被替换为 SQL 结果数组；嵌套模板可用；派生变量与表达式覆盖在 §2.12 验收线

### 2.6 Token 认证模拟

#### 背景说明

ManageOne 和 eSight 等网管系统有各自的鉴权接口（如 `POST /rest/manage/user/login`、`POST /api/session/login`），这些接口本身是用户配置的 mock API，mock 响应即为"颁发 token"行为。

`tokens` 表的作用是**已颁发 token 的注册表**（而非自动颁发），需要测试工程师手动录入 token 记录，pipeline 据此校验。

#### 校验规则

- 三种 auth 类型：`none` / `xtoken`（header `X-Auth-Token`）/ `basic`（header `Authorization: Basic ...`）
- xtoken 校验 `tokens` 表：`token` 存在 AND `revoked = 0` AND `expires_at > now`
- basic 校验：`token` 字段当 username，`meta` 中存 password，逻辑同上

#### Token 注册表管理（admin API）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/api/tokens` | 分页列出（可按 `revoked` / 未过期过滤） |
| POST | `/admin/api/tokens` | 手动录入 Token 到注册表 |
| POST | `/admin/api/tokens/{token}/revoke` | 手动撤销 |
| DELETE | `/admin/api/tokens/expired` | 清理所有已过期 Token |

#### 验收

- 无 token 返回 40401；token 不存在返回 40401；过期 token 返回 40402；手动失效 token 返回 40403；basic 错误返回 40404。
- Token 撤销后立即生效（实时查库）。
- **注意**：auth 接口本身的 mock 响应由用户在接口配置中自行定义，不在本模块范围内。

### 2.7 自动保存（60s）

- 前端 `topologyStore` 维护 `dirty` 标志；60s 定时器 + 退出前 `beforeunload` 提示
- 后端收到保存请求 → 事务写 `nodes/edges/node_attrs/edge_attrs/canvas_nodes` → WS 推 `topology.saved`
- **验收**：60s 内无操作自动触发；保存成功前端角标由"未保存"→"已保存 HH:MM"；网络失败时角标红色提示"保存失败（重试中）"。

### 2.8 WebSocket 推送

- 单一连接 `/admin/ws`；订阅模型：客户端发 `{op:'subscribe', topics:['topology.saved','api.registered']}`
- 心跳：ping/pong 30s
- **验收**：所有事件按订阅投递；断线自动重连（前端）。

### 2.9 画布性能（3 万节点）

- **AntV X6 优化**：开启 `async: true`、`frozen: true`（大图模式）；节点用 HTML 节点改为 SVG 形状；超过 500 节点时关闭动画
- **数据加载**：`GET /topologies/{id}/graph` 一次性返回全图 JSON（< 10MB for 3 万节点）；前端本地过滤
- **验收**：3 万节点加载 < 3s；拖动单节点 60fps；缩放/平移不卡顿。

### 2.10 请求规格与校验（M5 新增）

#### 背景

M4 之前的接口配置仅声明响应形态（响应模板 / 静态响应体），不声明请求形态——调用方该带哪些 query / header / body 完全靠口口相传，且后端只在 SQL 数据源下通过 `ParamMappingTable` 间接消费请求字段，静态模式完全忽略请求。`/oauth/token` 类业务接口对入参约束有真实需求（grantType=password 必填、networkId 必填等）。

#### 数据模型

`api_configs.config` 新增 `auth` 与 `request` 两段（均可缺省，缺省时行为与 M4 完全一致）：

```typescript
config: {
  // M4 已有字段保持不变
  params?: ParamMapping[]      // SQL :xxx 绑定表
  response?: { template, statusCode, contentType }
  staticBody?: unknown
  fault?: { delayMs, errorRate, errorStatus }

  // M5 新增
  auth?: {
    type: 'none' | 'xtoken' | 'basic'
    headerName?: string        // xtoken 默认 'X-Auth-Token'
  }
  request?: {
    headers?: HeaderSpec[]     // { name, required, expectValue?, example?, description? }
    query?: QuerySpec[]        // { name, type:'string'|'int'|'bool', required, example?, description? }
    body?: BodySpec            // { contentType, required, example? }
  }
}
```

#### 校验时机与顺序

`request_pipeline.py` 在 step 3（authenticate）之后、step 4（fault）之前插入 `_step3_5_validate_request`：

> 缺 token → 401（不让看），带 token 但参数缺 → 400。最小信息泄露原则。

#### 校验规则

- **headers**：声明的字段做 required + expectValue 严格匹配；**不**做白名单（HTTP 标准头如 User-Agent / Accept 由浏览器/curl 自动注入，强制白名单会使所有调用失败）
- **query**：声明的字段做 required + 类型校验；**严格白名单**——未声明的 query key 直接 400 拒绝（决策来源：用户 2026-04-29 拍板）
- **body**：仅校验 required；schema 校验本期不做（example 只用于文档展示）
- **未声明 `config.request`**：完全跳过校验（向后兼容 M4 接口）

#### 错误码段位（40020-40029）

| 错误码 | HTTP | 含义 |
|---|---|---|
| 40020 | 400 | 缺少必填请求头 |
| 40021 | 400 | 请求头值不匹配 expectValue |
| 40022 | 400 | 缺少必填 query 参数 |
| 40023 | 400 | query 参数类型错误 |
| 40024 | 415 | （**预留**给 LEGACY-02 content-type 校验） |
| 40025 | 400 | 严格模式下出现未声明的 query 参数 |
| 40026 | 400 | 请求体必填但为空 |
| 40027-40029 | — | 预留 |

#### 验收

- 严格模式：调用 `?foo=1`（未声明 foo）→ 400 + 40025
- 必填缺：声明 `userName` 必填但请求未带 → 400 + 40022
- 类型错：声明 `pageNo` 为 int，请求带 `pageNo=abc` → 400 + 40023
- expectValue：声明 `Content-Type` expectValue=`application/json`，请求带 `text/plain` → 400 + 40021
- body 必填：声明 body required=true，请求空 body → 400 + 40026
- 全通过：所有声明字段满足 → 走入 step 4 fault → step 5 execute → 200
- 鉴权（顺手 LEGACY-01）：UI 配 `auth.type=xtoken`，调用方带正确 token → 200，无 token → 401 + 40401

### 2.11 请求参数 → SQL 编辑器联动（M5-04b）

#### 背景

M5-04 完成后，`ParamMappingTable` 的参数名列已支持从已声明的 query/body 字段中下拉选择。但用户在编写 SQL 时还需要把请求参数以 `:paramName` 形式填入 SQL（如 `WHERE status = :status AND topology_id = :topologyId`），目前必须手工敲冒号+参数名——没有快捷插入入口。`SqlViewPanel`（SQL 编辑器左侧面板）已有"点击视图名 / 列名插入"的交互模式，自然应扩展为"点击请求参数名插入 `:<字段名>`"。

#### 数据流

```
ApiConfigModal
  └─ availableFieldNames: computed (来自 requestQuery[].name + body example JSON 键名)
       ├─ 传给 ParamMappingTable     (M5-04 已完成)
       └─ 传给 SqlViewPanel         (M5-04b 新增)
            └─ 点击 → emit('insert', ':<fieldName>')
                 └─ ApiConfigModal.handleInsertFromPanel()
                      └─ SqlEditor.insertAtCursor(':<fieldName>')
```

#### SqlViewPanel 改动

- **新增 prop**：`requestFieldNames?: string[]`（由父组件 `ApiConfigModal` 传入 `availableFieldNames`）
- **新增 UI 段**：在现有 `Collapse`（节点视图 / 边视图 / 通用视图）下方，新增一个独立区域"请求参数"
  - 标题行："请求参数 (N)"，与上方视图面板用分隔线隔开
  - 内容：N > 0 时，以 `Tag`（等宽字体）列出所有字段名，点击即 `emit('insert', ':' + fieldName)`；hover 时变色提示可点击
  - 空态：N = 0 时显示淡色文字"暂无可用的请求参数（请先在"请求规格"中声明 query 或 body 字段）"
  - 不放入 Collapse：此区域内容少且高频使用，直接平铺展示，无需折叠

#### ApiConfigModal 改动

- 模板中 `<SqlViewPanel>` 增加 `:request-field-names="availableFieldNames"` 绑定

#### 验收

- `availableFieldNames` 为空时（未声明任何 query/body 字段），SqlViewPanel 底部显示空态文案
- 声明 3 个 query 字段后，SqlViewPanel 底部展示 3 个可点击 Tag
- 点击 Tag 后 SQL 编辑器光标位置插入 `:fieldName`（如 `:topologyId`）
- 声明 body example `{"userName":"a","grantType":"b"}` 后，对应的 `:userName` / `:grantType` 也出现在列表中
- query 和 body 字段合并去重排序展示

### 2.12 响应模板派生变量与表达式引擎（M6 LEGACY-05 修复）

#### 背景

LEGACY-05 (2026-05-02 记录)：响应模板上下文 `_build_context` (`backend/app/core/response_template.py:54-68`) 仅暴露 `items / total / page / pageNo / pageSize / uuid / now` 7 个变量，且 `_PLACEHOLDER_RE` 仅匹配单一标识符，**无法表达 `totalPageNo = ceil(total/pageSize)` 类派生量**。用户配置 ManageOne CMDB `CLOUD_VM` 接口时识别出该缺口，决定通过两阶段串行实施修复。

#### 决策

1. **B + C 双轨实施**：派生变量集（B）+ 轻量表达式引擎（C）并存，B 是默认推荐路径，C 是高阶能力
2. **阶段拆分（串行）**：Phase 1（B）独立交付，验证后再开 Phase 2（C），分两次 PR/commit，降低单次回归压力
3. **明确不做**：模板条件分支、字符串字面量与拼接、循环、自定义函数、Lambda（留独立 LEGACY 出口）
4. **错误码**：复用现有 40303，无新增；任何表达式异常一律收口为 `TemplateRenderError`

#### Phase 1：派生变量集（方案 B）

**新增上下文变量**（追加到 `_build_context`）：

| 占位符 | 公式 | 类型 | 别名 |
|---|---|---|---|
| `{{totalPageNo}}` | `ceil(total / pageSize) if pageSize > 0 else 0` | int | `{{totalPages}}` |
| `{{hasNext}}` | `page < totalPageNo` | bool | — |
| `{{hasPrev}}` | `page > 1 and total > 0` | bool | — |
| `{{offset}}` | `(page - 1) * pageSize` | int | — |
| `{{count}}` | `len(items)` | int | — |

**边界矩阵**：

| total | pageSize | page | totalPageNo | hasNext | hasPrev | offset | count |
|---|---|---|---|---|---|---|---|
| 0 | 100 | 1 | 0 | false | false | 0 | 0 |
| 100 | 100 | 1 | 1 | false | false | 0 | 100 |
| 28 | 100 | 1 | 1 | false | false | 0 | 28 |
| 250 | 100 | 2 | 3 | true | true | 100 | 100 |
| 250 | 100 | 3 | 3 | false | true | 200 | 50 |
| 任意 | 0 | 任意 | 0 | false | — | 0 | len(items) |

**改动锚点**：
- `backend/app/core/response_template.py:1-23` docstring 占位符列表 +6
- `backend/app/core/response_template.py:54-68` `_build_context` +6 keys，`import math`
- 不动 `_PLACEHOLDER_RE` / `_render_str` / `_render_node`

#### Phase 2：表达式引擎（方案 C）

**语法（EBNF）**：

```ebnf
expression  = term { ("+" | "-") term } ;
term        = factor { ("*" | "/" | "%") factor } ;
factor      = ("+" | "-") factor | primary ;
primary     = NUMBER | IDENTIFIER | function_call | "(" expression ")" ;
function_call = IDENTIFIER "(" [ expression { "," expression } ] ")" ;
```

**显式禁用**：`**`（DOS 隐患）、`//`（用 `floor(a/b)` 代替）、位运算、比较、布尔运算、字符串字面量、列表/dict 字面量、Lambda、IfExp。

**AST 节点白名单**：`Expression / BinOp / UnaryOp / Add / Sub / Mult / Div / Mod / USub / UAdd / Constant(仅 int|float) / Name(Load) / Call(func 必为 Name 且在函数白名单)`。

**函数白名单**（共 7 个，定稿不再扩展）：

| 函数 | 实现 | 元数 |
|---|---|---|
| `ceil` | `math.ceil` | 1 |
| `floor` | `math.floor` | 1 |
| `round` | `round`（半向偶数） | 1 |
| `abs` | `abs` | 1 |
| `min` | `min(a, b)` | 严格 2，不支持 3+ 参数 |
| `max` | `max(a, b)` | 严格 2 |
| `int` | `int`（截断） | 1 |

**资源上限**：表达式串长度 ≤ 200 字符；AST 节点数 ≤ 50；数值结果绝对值 ≤ 10^15。

**dispatch 策略**（`_render_str` 改造）：
1. `_PLACEHOLDER_RE` 升级为非贪婪 `\{\{\s*(.+?)\s*\}\}`
2. 占位符 body 若匹配纯标识符 → 走旧路径（ctx 字典查找；未命中透传字面量）
3. 否则 → 走 `_eval_expression(body, ctx)` 新路径（任何错误抛 `TemplateRenderError`，不静默透传）

**类型保留**：whole-string 占位（如 `"x":"{{total+1}}"`）替换为原生数值；in-string 占位（如 `"page {{pageNo+1}}"`）按 `_stringify` 规则字符串化。

**错误处理**：所有失败路径统一映射 `TemplateRenderError` → 上游 pipeline 已映射 HTTP 400 + code 40303，无新增错误码。错误消息格式：`表达式语法错: <原因>` / `表达式禁用语法: <node>` / `表达式未定义变量: <name>` / `表达式未授权函数: <name>` / `表达式除零` / `表达式数值溢出 (>10^15)` / `表达式过长 (>200 chars)` / `表达式过于复杂 (>50 nodes)`。

**改动锚点**：
- `backend/app/core/response_template.py` 新增 `_eval_expression` / `_eval_node` / `_FUNC_TABLE` / `_BINOP_TABLE` / `_check_whitelist`；改写 `_PLACEHOLDER_RE`；`_render_str` dispatch 分支
- 不拆文件（response_template.py 加表达式逻辑后约 250 行，单文件可读性仍佳）

#### 安全决策（Phase 2 review 前置清单）

1. ✅ 绝不用 `eval()` / `exec()` / `compile(mode='exec')`
2. ✅ AST 节点白名单 > 黑名单
3. ✅ 禁止属性访问（`Attribute`）、下标（`Subscript`）、Lambda、IfExp、Compare、BoolOp、Starred、keyword args
4. ✅ 函数白名单 7 个固定，不放宽
5. ✅ 资源上限三道闸：长度 200 / AST 节点 50 / 数值 10^15
6. ✅ bool 类型自动转 int（`hasNext * 10`）—— 但禁止 bool 字面量出现在表达式（无 True/False 关键字支持）

### 2.13 接口拓扑绑定可修改（LEGACY-06 修复）

#### 背景

LEGACY-06（2026-05-03 记录）：`/apis` 编辑接口弹窗里的"绑定拓扑"Select 在编辑模式下被前端强制 `:disabled="isEdit"`（`ApiConfigModal.vue:535`），用户已配好的接口若要换拓扑只能删除重建。但**后端 `PATCH /apis/{id}/topology` 端点早已就位**——这是一个被前端单向锁住的已有能力。

#### 决策（已与用户对齐 5 项）

1. **解锁 Select**：编辑模式下允许切换拓扑
2. **二次确认弹窗**：切换瞬间弹 `Modal.confirm` 提示风险，**用户取消则回滚 Select 值**
3. **保留 sqlText**：默认不清空（避免破坏性丢失工作），弹窗内提供"切换时同时清空 SQL"**可选 checkbox**
4. **SQL 视图引用预扫描**：新增后端端点 `GET /apis/{id}/topology-switch-preview?targetTopologyId=xxx`，解析 sqlText 提 `FROM/JOIN <name>` 与目标拓扑 `collect_views()` 做差集，返回 `missingViews`；前端在二次确认弹窗里直接呈现
5. **不立 M7 主版本**：作为 LEGACY-06 随手实施

#### 数据模型

零变更。`api_configs.topology_id` 已是可空 FK，PATCH 端点已存在。

##### 5.2 新增 GET /apis/{api_id}/topology-switch-preview

```
GET /admin/api/apis/{api_id}/topology-switch-preview?targetTopologyId=<id>

200 OK:
{
  "code": 0,
  "data": {
    "missingViews": ["switches", "old_view_name"],   // 新拓扑下不存在的视图引用
    "availableViews": ["routers", "ports", ...],      // 目标拓扑下可用的全部视图名
    "currentSqlReferences": ["switches", "ports"],    // 当前 sqlText 解析出的视图引用
```

实现要点：
- 复用 `app.core.cte_builder.collect_views(conn, topology_id)` 取目标拓扑视图清单
- SQL 引用解析：用正则 `r"\b(?:FROM|JOIN)\s+(\w+)"`（i 模式）粗扫，收集所有标识符

- 空 sqlText / 空 SQL 引用 → `missingViews=[]`、`warning=null`（友好降级）
- targetTopologyId 与当前 topology_id 相同 → 仍正常返回（前端不会触发该端点，但后端不限制）

## 6. 风险与应对（MVP 关注项）

| 风险 | 影响 | 应对 |
|------|------|------|
| SQLite 并发写入瓶颈 | 自动保存与多 Tab 并发写入冲突 | 单写线程 + WAL 模式（`PRAGMA journal_mode=WAL`） |
