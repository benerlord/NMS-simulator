# 节点名称优化 - 开发方案（修订版）

## 问题回顾

1. 画布上创建节点后无法重命名
2. 节点类型定义的自定义字段（如 `field_key="name"`）与节点显示名称脱节

上一版方案引入了 `name_field_key` 的间接映射，过于复杂。

---

## 修订方案：name 作为系统内置属性

### 核心思路

**`name` 是所有节点类型自带的系统属性，直接映射到 `nodes.name` 列。不需要在 `node_type_fields` 中定义，也不需要 `name_field_key` 映射。**

```
画布标签  ←  nodes.name  ←  创建/编辑时用户手动输入
                              ↑
                        系统内置，不属于 node_type_fields
```

| 对比 | 上一版（name_field_key） | 修订版（系统内置 name） |
|------|------------------------|----------------------|
| 数据模型 | node_types 加列 + 关联到某个 field_key | 零改动，复用 nodes.name |
| 配置方式 | 类型管理中选哪个字段是"名称字段" | 无需配置，name 永远存在 |
| 创建节点 | name 绑定到指定字段的值 | name 是一个独立必填输入框 |
| 编辑节点 | 修改那个字段 → 自动同步 name | 直接修改 name 输入框 |
| 复杂度 | 高（8 个文件，含迁移） | 低（4 个文件，无迁移） |

---

## 方案分析

### 优点

1. **零数据模型改动** — `nodes.name` 列已存在（NOT NULL），它本来就是画布标签的数据源（`nodeShape.ts:41` 的 `buildInfraNodeAttrs` 第二个参数就是 name）
2. **语义天然正确** — 节点的名称就是 `name`，不需要"用另一个字段的值去覆盖 name"
3. **前后端一致** — 创建 `POST /nodes { name }`，更新 `PUT /nodes/{id} { name }`，API 已完整支持
4. **无配置负担** — 不需要在类型管理中设置"哪个字段是名称字段"

### 潜在问题及对策

#### 问题 1：与自定义字段 `field_key="name"` 的冲突

如果用户在节点类型中创建了一个 `field_key="name"` 的自定义字段，它和系统内置的 `name` 可能混淆。

**当前种子数据**：11 个节点类型均无 `field_key="name"` 的字段（seed.py 中字段只有 vendor、model、ip、type 等）。

**对策**：
- 系统 `name` 在 UI 中始终以 **"节点名称"** label 展示，独立于自定义字段区域
- 自定义字段 `field_key="name"` 的 label 由用户定义（如"名称"），两者在 UI 上可区分
- **不强限制**创建 `field_key="name"` 的自定义字段，因为存储路径不同（`nodes.name` vs `node_attrs.name`），不会互相覆盖

#### 问题 2：创建节点时的默认名称

当前 `NodeAttrsModal.vue:33` 自动生成 `"{TypeName}_{timestamp36}"` 作为默认名称。

**对策**：保留自动生成的默认值，但：
- 输入框获得焦点时全选文本，用户可直接键入覆盖
- placeholder 提示"请输入节点名称"
- 校验：不允许为空

这样兼顾效率（大多数时候默认值够用）和可定制性（需要时可以改）。

#### 问题 3：节点名称唯一性

`nodes` 表对 `name` 没有唯一约束（仅 `dn` 有拓扑内唯一约束）。多个节点可以同名。

**分析**：不做唯一限制。实际场景中同类型节点可以有相同名称（如多个"核心交换机"），用户通过位置区分。如有唯一性需求，后续可通过 `dn`（DN 模板）实现。

#### 问题 4：与节点组的 `name_template` 的关系

节点组使用 `name_template`（如 `{group}-{i:05d}`）批量生成节点名称（CTE 中 `group_nodes` 视图）。

**分析**：无冲突。节点组展开时自动填充 `nodes.name`，用户后续在属性面板中也可以手动修改这些名称。

## 实现设计

### 涉及文件（4 个，均为前端）

| 文件 | 改动内容 |
|------|---------|
| `frontend/src/components/canvas/NodeAttrsModal.vue` | 优化"节点名称"输入框交互（全选默认值 + placeholder + 校验文案） |
| `frontend/src/components/canvas/NodeAttrsPanel.vue` | 名称从只读 `<div>` 改为可编辑 `<Input>`，保存时调用 `nodeApi.update` |
| `frontend/src/components/canvas/CanvasView.vue` | 新增 `handleNodeRename(nodeId, newName)` 刷新画布标签 |
| `frontend/src/components/canvas/NodeAttrsModal.vue` | 创建后 emit name → CanvasView 已支持（第 954 行传 name），无需改动 |

### 改动 1：NodeAttrsModal — 创建时名称输入优化

**现状：**
```html
<Input v-model:value="nodeName" placeholder="请输入节点名称" />
```
默认值 `"{TypeName}_{timestamp36}"`，用户可改可不改。

**改为：**
```html
<Input
  v-model:value="nodeName"
  placeholder="请输入节点名称，如 core-switch-01"
  @focus="onNameFocus"
/>
```

```typescript
// 聚焦时全选默认文本，方便用户直接覆盖
function onNameFocus(e: Event) {
  const input = e.target as HTMLInputElement
  input.select()
}
```

校验不变（已经有 `nodeNameError` 和空值检查）。

### 改动 2：NodeAttrsPanel — 名称可内联编辑

**现状（line 117）：**
```html
<div class="node-name">{{ nodeName }}</div>
```

**改为：**
```html
<div class="node-name-row">
  <span class="node-name-label">节点名称</span>
  <Input
    :value="editingName"
    @change="onNameChange"
    :maxlength="100"
  />
</div>
```

**新增逻辑：**
```typescript
const editingName = ref('')

watch(() => props.nodeName, (v) => { editingName.value = v })
// 或者直接初始化时同步

function onNameChange(e: any) {
  const newName = e.target.value
  editingName.value = newName
  // 不立即保存，等用户点"保存"按钮时一起提交
}
```

**保存时一并更新名称：**
```typescript
async function handleSave() {
  // ... 现有 attrs 保存逻辑 ...

  // 如果名称有变更，同步更新 nodes.name
  if (editingName.value !== props.nodeName && editingName.value.trim()) {
    await nodeApi.update(props.nodeId, { name: editingName.value.trim() })
    emit('rename', props.nodeId, editingName.value.trim())
  }
}
```

**新增 emit：**
```typescript
const emit = defineEmits<{
  (e: 'close'): void
  (e: 'update', nodeId: string, attrs: Record<string, string | null>): void
  (e: 'delete', nodeId: string, nodeName: string): void
  (e: 'rename', nodeId: string, newName: string): void  // 新增
}>()
```

### 改动 3：CanvasView — 响应名称变更

**新增事件处理：**
```typescript
function handleNodeRename(nodeId: string, newName: string) {
  const node = g.value?.getCellById(nodeId)
  if (node) {
    node.attr('label/text', newName)
    node.setData({ ...node.getData(), name: newName })
  }
}
```

**模板绑定：**
```html
<NodeAttrsPanel
  ...
  @rename="handleNodeRename"
/>
```

### 不需要改动的部分

- **后端 `node.py`** — `POST /nodes` 和 `PUT /nodes/{id}` 已完整支持 name 的创建和更新
- **后端 `node_type.py`** — 不需要 `name_field_key`
- **数据库** — 不需要迁移
- **类型管理 UI** — 不需要在字段列表中展示"name"（它是系统属性，存在于所有类型）
- **画布渲染** — `buildInfraNodeAttrs(code, name)` 不变，只需传入的 name 值正确

## 交互流程

### 创建节点

```
拖拽类型到画布
  → NodeAttrsModal 弹出
  → "节点名称"输入框显示默认值 "交换机_lx4p8a"（全选状态）
  → 用户直接键入 "core-switch-01" 覆盖
  → 点击"创建"
  → POST /topologies/{id}/nodes { name: "core-switch-01", ... }
  → 画布显示 "core-switch-01"
```

### 重命名节点

```
双击节点
  → NodeAttrsPanel 打开
  → 顶部"节点名称"输入框显示当前名称 "core-switch-01"
  → 用户修改为 "core-switch-02"
  → 修改属性字段...
  → 点击"保存"
  → PUT /nodes/{id}/attrs { ... attrs ... }
  → PUT /nodes/{id} { name: "core-switch-02" }
  → 画布标签刷新为 "core-switch-02"
```

## 测试要点

| 场景 | 预期 |
|------|------|
| 创建节点，保留默认名称 | 画布显示默认名称如 "交换机_abc123" |
| 创建节点，修改名称为自定义值 | 画布显示自定义名称 |
| 创建节点，名称为空点击创建 | 校验不通过，提示"节点名称不能为空" |
| 编辑节点，修改名称后保存 | 画布标签更新，再次打开面板显示新名称 |
| 编辑节点，清空名称后保存 | 不更新名称（trim 后为空则跳过） |
| 编辑节点，只改名称不改属性 | 名称更新成功 |
| 编辑节点，改属性不改名称 | 不调用 `PUT /nodes/{id}`，无多余请求 |
| 重命名后刷新页面 | 名称持久化，画布显示新名称 |
| 节点组展开的节点 | 名称由 `name_template` 生成，可在面板中手动重命名 |

## 与上一版方案对比

| | name_field_key 方案 | 系统内置 name 方案 |
|---|---|---|
| 数据库迁移 | 需要 | **不需要** |
| 后端改动 | Schema + 2 个路由 | **不需要** |
| 前端改动 | 8 个文件 | **4 个文件** |

| 理解成本 | 需理解"名称字段"概念 | **直觉一致** |
