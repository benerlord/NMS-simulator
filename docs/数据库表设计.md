# 网管系统模拟工具 - 数据库表设计文档

## 1. 概述

### 1.1 设计原则

- **双库分离**：持久化库（SQLite 文件）存储配置和历史，内存库（SQLite `:memory:`）承载运行时查询
- **JSON 存储大对象**：拓扑数据、接口配置等复杂结构使用 JSON 字段存储，减少表关联
- **结构化存储独立实体**：需要独立查询、排序、筛选的实体使用独立表和结构化字段
- **SQLite 兼容语法**：所有 DDL 使用 SQLite 语法，不依赖 MySQL/PostgreSQL 特有功能

### 1.2 数据库文件

| 数据库 | 文件 | 用途 |
|--------|------|------|
| 持久化库 | `./data/app.db` | 拓扑、配置、日志等持久化数据 |
| 内存库 | `:memory:` | 运行时虚拟表，供 HTTP Mock Server SQL 查询 |

### 1.3 字段命名约定

| 约定 | 示例 |
|------|------|
| 表名：小写 + 下划线 | `api_configs` |
| 字段名：小写 + 下划线 | `created_at` |
| 主键：`id` | `TEXT` 类型，应用层生成（UUID 或带前缀的 ID） |
| 时间字段：ISO 8601 字符串 | `2026-04-12T15:20:00Z` |
| 布尔字段：`INTEGER`（0/1） | SQLite 无原生 BOOLEAN |
| JSON 字段：`TEXT` | SQLite 3.38+ 支持 `json()` 函数 |

### 2.3 topologies — 拓扑图

存储拓扑的完整快照。核心拓扑数据（设备、端口、链路、告警、指标、画布状态）以 JSON 存储在 `data` 字段中。

**设计决策：** 拓扑数据结构复杂且高度耦合（设备 → 端口 → 链路互相引用），拆成关系表会导致加载/保存时大量 JOIN，而本系统的核心模式是"整体加载到内存 → 内存编辑 → 整体保存"，JSON 大对象更合适。

```sql
CREATE TABLE topologies (
    id          TEXT PRIMARY KEY,               -- 拓扑 ID，如 'topo_001'
    name        TEXT NOT NULL,                   -- 拓扑名称
    description TEXT DEFAULT '',                 -- 拓扑描述
    data        TEXT NOT NULL DEFAULT '{}',      -- 拓扑完整数据（JSON）
    version     INTEGER DEFAULT 1,               -- 当前版本号，每次保存 +1
    is_active   INTEGER DEFAULT 0,               -- 是否为当前活跃拓扑（0/1），全局仅一个为 1
    created_at  TEXT DEFAULT (datetime('now')),   -- 创建时间
    updated_at  TEXT DEFAULT (datetime('now'))    -- 最后更新时间
);

CREATE INDEX idx_topologies_active ON topologies(is_active);
CREATE INDEX idx_topologies_updated ON topologies(updated_at);
```

**JSON 大小估算（3 万设备场景）：**

| 数据 | 估算行数 | 单条约大小 | 合计 |
|------|----------|-----------|------|
| devices | 30,000 | 300 B | ~9 MB |
| ports | 72,000（平均每设备 2.4 端口） | 200 B | ~14 MB |
| links | 40,000 | 250 B | ~10 MB |
| alarms | 5,000 | 200 B | ~1 MB |
| metrics | 30,000 | 150 B | ~4.5 MB |
| canvas | 30,000 节点位置 | 30 B | ~1 MB |
| **合计** | | | **~40 MB** |

SQLite 单字段存储 40 MB JSON 没有问题，读写性能在可接受范围内（加载 < 1s，保存 < 2s）。

### 2.4 topology_history — 拓扑版本历史

每次拓扑保存时写入一条历史记录，用于版本回退。通过触发器或应用层控制最大版本数。

```sql
CREATE TABLE topology_history (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    topology_id  TEXT NOT NULL,                   -- 关联拓扑 ID
    version      INTEGER NOT NULL,                -- 版本号
    data         TEXT NOT NULL,                    -- 该版本的完整拓扑数据（JSON）
    device_count INTEGER DEFAULT 0,               -- 快照统计：设备数
    port_count   INTEGER DEFAULT 0,               -- 快照统计：端口数
    link_count   INTEGER DEFAULT 0,               -- 快照统计：链路数
    created_at   TEXT DEFAULT (datetime('now')),   -- 保存时间

    FOREIGN KEY (topology_id) REFERENCES topologies(id) ON DELETE CASCADE
);

CREATE INDEX idx_topo_history_tid_ver ON topology_history(topology_id, version DESC);
```

**版本清理策略：** 应用层在每次写入新版本后，删除超出保留数量的旧版本：

```sql
-- 保留最近 N 个版本，删除更早的
DELETE FROM topology_history
WHERE topology_id = :tid
  AND id NOT IN (
    SELECT id FROM topology_history
    WHERE topology_id = :tid
    ORDER BY version DESC
    LIMIT :max_versions
  );
```

### 2.6 api_configs — HTTP 接口配置

存储用户配置的模拟 HTTP 接口。每条记录定义一个完整的接口。

```sql
CREATE TABLE api_configs (
    id              TEXT PRIMARY KEY,                -- 配置 ID，如 'api_001'
    name            TEXT NOT NULL,                   -- 接口名称
    group_name      TEXT DEFAULT '',                  -- 分组名称，如 'ManageOne', 'eSight'
    enabled         INTEGER DEFAULT 1,               -- 是否启用（0/1）

    -- 路由
    method          TEXT NOT NULL,                    -- HTTP 方法: GET / POST / PUT / DELETE
    path            TEXT NOT NULL,                    -- 路由路径: /rest/openapi/...

    -- 认证配置（JSON）
    auth            TEXT DEFAULT '{"type":"none"}',

    -- 数据源配置（JSON）
    data_source     TEXT NOT NULL,

    -- 查询参数配置（JSON）
    query           TEXT DEFAULT '{"params":[],"pagination":{"enabled":false}}',

    -- 响应模板配置（JSON）
    response        TEXT DEFAULT '{"contentType":"application/json","template":{}}',

    -- 异常模拟配置（JSON）
    fault           TEXT DEFAULT '{"delay":0,"errorRate":0,"errorStatus":500}',

    created_at      TEXT DEFAULT (datetime('now')),
    updated_at      TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_api_configs_group ON api_configs(group_name);
CREATE INDEX idx_api_configs_enabled ON api_configs(enabled);
CREATE UNIQUE INDEX idx_api_configs_route ON api_configs(method, path);
```

**`auth` 字段 JSON 结构：**

```json
// 无认证
{ "type": "none" }

// xToken 认证
{
  "type": "xtoken",
  "headerName": "X-Auth-Token"
}

// Basic 认证
{
  "type": "basic"
}
```

**`data_source` 字段 JSON 结构：**


### 2.7 session_config — Token 认证配置

全局 Token 认证参数。单行配置表。

```sql
CREATE TABLE session_config (
    id              TEXT PRIMARY KEY DEFAULT 'default',  -- 固定 'default'
    token_expiry    INTEGER DEFAULT 1800,                 -- Token 有效期（秒）
    credentials     TEXT DEFAULT '[]',                    -- 用户名密码列表（JSON）
    updated_at      TEXT DEFAULT (datetime('now'))
);
```

**`credentials` 字段 JSON 结构：**

```json
[
  { "username": "IMOCTest", "password": "Imoc@12345" },
  { "username": "admin",   "password": "admin123" }
]
```

**说明：** 运行时的 Token 表（token → 过期时间）仅存在于内存中（`SessionManager`），不持久化。Token 的生命周期短暂，重启后需要插件重新登录，无需持久化。

### 2.9 snmp_oid_configs — SNMP OID 配置

每个 OID 一行，支持独立的增删改查、搜索和分组筛选。

```sql
CREATE TABLE snmp_oid_configs (
    id            TEXT PRIMARY KEY,                -- OID 配置 ID
    oid           TEXT NOT NULL,                   -- OID 值: 1.3.6.1.2.1.1.1.0
    name          TEXT DEFAULT '',                  -- OID 名称: sysDescr
    group_name    TEXT DEFAULT 'default',           -- 分组: system / interface / custom
    device_type   TEXT DEFAULT '',                  -- 关联设备类型，空表示通用
    data_type     TEXT NOT NULL,                   -- 数据类型: OctetString / Integer32 / Counter32 / Counter64 / Gauge32 / TimeTicks
    value_source  TEXT DEFAULT 'static',           -- 取值来源: static / topology / expression
    value_config  TEXT NOT NULL DEFAULT '{}',      -- 取值配置（JSON）
    description   TEXT DEFAULT '',                  -- 描述信息
    enabled       INTEGER DEFAULT 1,               -- 是否启用（0/1）
    created_at    TEXT DEFAULT (datetime('now')),
    updated_at    TEXT DEFAULT (datetime('now'))
);

CREATE UNIQUE INDEX idx_snmp_oid ON snmp_oid_configs(oid);
CREATE INDEX idx_snmp_oid_group ON snmp_oid_configs(group_name);
CREATE INDEX idx_snmp_oid_device_type ON snmp_oid_configs(device_type);
```

**`value_config` 字段 JSON 结构（按 `value_source` 不同）：**

```json
// static: 固定值
{
  "value": "Huawei CE6800 Switch"
}

// topology: 从拓扑数据映射
{
  "mapping": "device.name",
  "deviceSelector": "byIndex"
}

// expression: 表达式生成
{
  "expression": "random(0, 100)",
  "refreshInterval": 300
}
```

### 2.11 sftp_templates — SFTP 文件生成模板

每个模板定义一类文件的生成规则。

```sql
CREATE TABLE sftp_templates (
    id                TEXT PRIMARY KEY,               -- 模板 ID
    name              TEXT NOT NULL,                   -- 模板名称
    device_types      TEXT DEFAULT '[]',               -- 关联的设备类型列表（JSON 数组）
    file_type         TEXT NOT NULL DEFAULT 'csv',     -- 文件类型: csv / zip
    name_template     TEXT NOT NULL,                   -- 文件名模板
    generate_interval INTEGER DEFAULT 300,             -- 生成间隔（秒），默认 5 分钟
    enabled           INTEGER DEFAULT 1,               -- 是否启用（0/1）
    headers           TEXT DEFAULT '[]',               -- CSV 表头定义（JSON 数组）
    created_at        TEXT DEFAULT (datetime('now')),
    updated_at        TEXT DEFAULT (datetime('now'))
);
```

**`device_types` 字段：**

```json
["switch", "router"]
```

**`name_template` 示例：**

- CSV: `PM_IGHostPerfStat_5_{timestamp}_partition_{seq}.csv`

| 占位符 | 说明 | 示例 |

| `{date}` | 日期 `YYYYMMDD` | `20260412` |
| `{time}` | 时间 `HHmm` | `1520` |

## 3. 内存库（SQLite :memory:）

### 3.7 内存表字段命名与 API SQL 的映射

用户在 HTTP 接口配置中编写的 SQL 使用 **camelCase** 字段名（与需求文档和 API 响应一致），内存表使用 **snake_case**。通过 SQLite 的列别名在建表时解决：

**方案：建表时使用 camelCase 列名**

为降低用户心智负担，内存表直接使用 camelCase 列名，使用户编写的 SQL 无需转换：

```sql
-- 实际建表语句（内存库使用 camelCase）
CREATE TABLE devices (
    id           TEXT PRIMARY KEY,
    name         TEXT,
    type         TEXT,
    dn           TEXT,
    ip           TEXT,
    vendor       TEXT,
    model        TEXT,
    status       TEXT,
    portCount    INTEGER DEFAULT 0,
    customFields TEXT DEFAULT '{}'
);
```

这样用户可以直接写 `SELECT * FROM devices WHERE type = :type`，无需关心字段映射。

### 3.8 数据同步机制

TopologyManager 数据变更时，将数据同步到内存 SQLite 表。

**同步时机：**

| 场景 | 策略 | 说明 |
|------|------|------|
| 拓扑加载/切换 | 全量同步 | 清空所有表 → 批量 INSERT |
| 单个设备增改删 | 增量同步 | INSERT/UPDATE/DELETE 对应行 |
| 批量操作 | 事务批量 | BEGIN → 多条操作 → COMMIT |
| 端口生成 | 批量 INSERT | 使用 `executemany()` |

**全量同步流程：**

```
TopologyManager.load_topology(topo_id)
    │
    ├── 1. 从 PersistStore 读取 topologies.data
    ├── 2. 解析 JSON，构建内存对象
    ├── 3. 调用 MemoryStore.full_sync(topology_data)
    │       ├── BEGIN TRANSACTION
    │       ├── DELETE FROM devices
    │       ├── DELETE FROM ports
    │       ├── DELETE FROM links
    │       ├── DELETE FROM alarms
    │       ├── DELETE FROM metrics
    │       ├── INSERT INTO devices VALUES (...), (...), ...  (executemany)
    │       ├── INSERT INTO ports VALUES (...), (...), ...
    │       ├── INSERT INTO links VALUES (...), (...), ...
    │       ├── INSERT INTO alarms VALUES (...), (...), ...
    │       ├── INSERT INTO metrics VALUES (...), (...), ...
    │       └── COMMIT
    └── 4. EventBus.emit("topology.loaded")
```

**全量同步性能预估（3 万设备）：**

| 操作 | 数据量 | 预估耗时 |
|------|--------|----------|
| DELETE 5 表 | - | < 10ms |
| INSERT devices | 30,000 行 | ~50ms |
| INSERT ports | 72,000 行 | ~100ms |
| INSERT links | 40,000 行 | ~60ms |
| INSERT alarms | 5,000 行 | ~10ms |
| INSERT metrics | 30,000 行 | ~50ms |
| **合计** | **177,000 行** | **~300ms** |

## 4. 数据库初始化

### 4.1 初始化流程

```
应用启动
  │
  ├── 1. 检查 data/ 目录是否存在，不存在则创建
  │
  ├── 2. 打开持久化库 (./data/app.db)
  │       ├── 启用 WAL 模式: PRAGMA journal_mode=WAL
  │       ├── 启用外键: PRAGMA foreign_keys=ON
  │       └── 执行建表迁移
  │
  ├── 3. 插入预置数据（IF NOT EXISTS）
  │       ├── device_types: 5 条预定义类型
  │       ├── protocol_configs: 4 条协议配置
  │       ├── session_config: 1 条默认配置
  │       ├── snmp_trap_config: 1 条默认配置
  │       └── system_settings: 11 条默认设置
  │
  ├── 4. 创建内存库 (:memory:)
  │       └── 创建 5 张虚拟表（camelCase 列名）
  │
  └── 5. 加载活跃拓扑到内存
          ├── 查询 is_active=1 的拓扑
          ├── 解析 data JSON
          └── 全量同步到内存库
```

### 4.2 数据库迁移

使用版本号管理数据库 schema 变更：

```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version     INTEGER PRIMARY KEY,              -- 迁移版本号
    description TEXT DEFAULT '',                   -- 迁移说明
    applied_at  TEXT DEFAULT (datetime('now'))     -- 应用时间
);
```

应用启动时检查当前 schema 版本，按序执行未应用的迁移。

### 4.3 SQLite 配置

```sql
-- 性能优化
PRAGMA journal_mode = WAL;          -- Write-Ahead Logging，提升并发读写
PRAGMA synchronous = NORMAL;        -- 平衡安全和性能
PRAGMA cache_size = -8000;          -- 8MB 缓存
PRAGMA temp_store = MEMORY;         -- 临时表存内存
PRAGMA mmap_size = 134217728;       -- 128MB mmap

-- 功能启用
PRAGMA foreign_keys = ON;           -- 启用外键约束
```
