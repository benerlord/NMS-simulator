# 接口子目录与复制功能 — 设计方案

## 背景

接口配置页面（ApisView）当前按 `category || domainName` 做单级分组。当一个网管/设备目录下有上百个接口时，缺乏二级分类能力，难以管理。同时，许多接口结构相似仅路由参数不同，缺少复制功能导致重复配置工作量大。

## 需求

1. **子目录**：在每个网管/设备目录下支持一层子目录，对接口进行二次分类
2. **接口复制**：复制已有接口并打开编辑弹窗，用户修改后保存为新接口

---

## 功能一：子目录（Sub-category）

### 数据模型

复用现有 `api_configs.category` 字段，不新增表。

- `category` 当前是纯文本标签（max 50 字符），前端按 `category || domainName || '__none__'` 分组
- 子目录按 domain 隔离：同一 domain 下 category 唯一，不同 domain 下同名 category 独立
- `category = NULL` 的接口归入该 domain 的"未分类"分组

### 后端 API

#### 查询子目录列表

```
GET /admin/api/domains/{domain_id}/categories
```

从 `api_configs` 中提取该 domain 下所有非空 DISTINCT category，按字母排序返回。

响应：
```json
{
  "code": 0,
  "data": ["资源查询", "告警管理", "拓扑管理"],
  "message": "ok"
}
```

#### 批量修改接口子目录

```
PUT /admin/api/apis/batch-category
```

请求体：
```json
{
  "api_ids": ["api_xxx", "api_yyy"],
  "category": "资源查询"
}
```

将指定接口的 `category` 批量设为新值。`category` 为 `null` 时清除分类。

#### 删除子目录

```
DELETE /admin/api/domains/{domain_id}/categories/{name}
```

将该 domain 下所有 `category = name` 的接口的 `category` 设为 `NULL`，然后返回成功。

#### 重命名子目录

```
PUT /admin/api/domains/{domain_id}/categories/{name}
```

请求体：
```json
{ "new_name": "新名称" }
```

批量 UPDATE 该 domain 下所有 `category = name` 的记录为 `new_name`。

### 前端改动

#### ApiConfigTable.vue

1. 每个 domain 分组头部新增"添加子目录"按钮（`FolderAddOutlined` 图标）
   - 点击后弹出 Input 确认框（类似 Inline Edit），输入名称后创建
   - 创建后自动刷新列表，新子目录作为子分组出现
2. 子目录分组头部新增操作：
   - 重命名（`EditOutlined`）— Inline Edit 改名
   - 删除（`DeleteOutlined`）— Popconfirm 二次确认，删除子目录（接口归入"未分类"）
3. 子目录分组内的接口列表与现有 domain 分组内的接口列表结构一致
4. 搜索联动：关键词匹配时自动展开包含匹配结果的子目录分组

#### ApiConfigModal.vue

1. 新增"所属子目录"字段（`a-select` 组件）
2. 选项来源：`GET /admin/api/domains/{domain_id}/categories`
3. 支持输入新名称直接创建（`mode="tags"` 或自定义下拉）
4. 仅在接口已关联 domain 时显示此字段

### 分组渲染逻辑

```
网管A (domain)
  ├── 资源查询 (category)  ← 子目录
  │   ├── 接口1
  │   └── 接口2
  ├── 告警管理 (category)  ← 子目录
  │   └── 接口3
  └── 未分类               ← category 为 NULL 的接口
      └── 接口4
```

## 功能二：接口复制

### 后端 API

```
POST /admin/api/apis/{id}/duplicate
```

逻辑：
1. 读取源接口全部字段（`SELECT * FROM api_configs WHERE id = ?`）
2. 生成新 ID：`api_{uuid.uuid4().hex[:12]}`
3. `name` 加 `"(副本)"` 后缀（如 `"设备查询"` → `"设备查询(副本)"`）
4. `path` 加 `"_copy"` 后缀（如 `/rest/v1/devices` → `/rest/v1/devices_copy`）
5. 复制所有其他字段（`method`, `data_source`, `sql_text`, `config`, `domain_id`, `category`, `topology_id`）
6. `enabled` 设为 `false`（副本默认禁用，避免冲突）
7. INSERT 新记录
8. 返回 `{"code": 0, "data": {"id": "api_xxx"}, "message": "ok"}`

path 唯一性：`api_configs` 有 `UNIQUE(method, path)` 约束。`_copy` 后缀保证不冲突。用户在编辑弹窗中可自行修改 path。

### 前端改动

#### api_config.ts

新增 API 方法：
```typescript
duplicate: (id: string): Promise<{ id: string }> =>
  apiPost(`/apis/${id}/duplicate`),
```

#### ApiConfigTable.vue

操作列新增"复制"按钮（`CopyOutlined` 图标），位于编辑和删除之间：
```html
<a @click="handleDuplicate(record)" title="复制"><CopyOutlined /></a>
```

`handleDuplicate` 函数：
1. 调用 `apiConfigApi.duplicate(record.id)`
2. 成功后打开 `ApiConfigModal`，传入新接口 ID（编辑模式）
3. 用户修改 name 和 path 后保存

## 验证方案

1. 子目录：在 domain 分组下创建子目录 → 移动接口到子目录 → 搜索联动 → 删除子目录（接口归入未分类）→ 重命名子目录
2. 复制：点击复制 → 弹窗预填数据 → 修改 name/path → 保存 → 验证新接口独立存在
3. 导入导出：导出含子目录的接口 → 导入 → 验证 category 字段保留
