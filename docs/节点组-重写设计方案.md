# 节点组 — 开发设计方案（重写版）

## 概述

在已有的普通节点画布功能之上，新增"节点组"功能：通过参数化定义批量生成大规模拓扑节点，用于性能压测和大规模场景模拟。

**核心设计原则：**
- 单一画布 — 宏节点（节点组）和普通节点共存于同一个 TopologyCanvas
- 零模式切换 — 不引入 viewMode 状态机，用户无感知切换
- 最小侵入 — 仅新增 GroupPalette + GroupCreateModal 两个组件，其余组件通过扩展而非替换的方式支持节点组

---

## 概念模型

```
节点组 (Node Group)
  ├── 定义: 节点类型 + 数量 + 属性策略 + 边策略
  ├── 未展开: 仅在画布上显示一个"宏节点"占位符
  └── 展开 (materialize): 将 N 个实体节点 + 边插入 DB，加载到画布

宏节点 (Macro Node)
  └── 画布上的可视化占位符，代表一个节点组
      双线边框矩形 + 组名 + 数量 + 状态条
```

## 架构设计

### 画布统一

**只保留一个 TopologyCanvas**，在其 `initGraph()` 中并行加载两类数据：

```
fetchGraph()         → { nodes[], edges[] }        普通节点 + 边
fetchGroupGraph()    → { macroNodes[], macroEdges[] } 宏节点 + 宏边
```

两类节点和边在同一 X6 Graph 实例中共存，使用不同的 Shape/样式区分。

### 数据流

```
CanvasView (provide 单例 useNodeGroups)
  ├── TopologyCanvas (inject)  ← 渲染普通节点 + 宏节点
  ├── TypePalette (自管)       ← 拖拽创普通节点
  ├── GroupPalette (inject)    ← 拖拽定位宏节点 + 右键操作
  ├── GroupCreateModal (inject)← 三步向导创建组
  ├── NodeAttrsPanel           ← 双击普通节点
  └── EdgeAttrsPanel           ← 双击普通边
```

**关键：** `useNodeGroups` 在 CanvasView 中创建一次，通过 `provide`/`inject` 共享给所有子组件。消除每个组件独立实例导致的状态不同步问题。

### 组件职责

| 组件 | 职责 | 本次改动 |
|---|---|---|---|
| CanvasView | provide composable，编排数据加载 | 新增 provide/inject；并行加载 groupGraph；合并左侧面板 |
| TopologyCanvas | 渲染普通节点 + 宏节点 + 边 + 连线 | 加载 groupGraph 数据；注册 macro-node Shape；连线模式支持混合连接 |
| TypePalette | 拖拽创建普通节点 | 宽度从 180px 调整为 200px，与 GroupPalette 对齐 |
| GroupPalette | 节点组列表 + 拖拽 + 右键菜单 | **新文件** |
| GroupCreateModal | 三步创建向导 | **新文件** |
| NodeAttrsPanel | 编辑普通节点属性 | 无需改动 |
| EdgeAttrsPanel | 编辑普通边属性 | 无需改动 |
| CanvasToolbar | 保存/撤销/缩放/连线 | 无需改动 |

**不引入的新文件。**

## 核心交互设计

### 1. 左侧面板

TypePalette（上）和 GroupPalette（下）始终同时显示，宽度统一 200px：

```
┌──────────────────┐
│ 节点类型          │  TypePalette (200px)
│  [交换机] [服务器] │
│  [路由器] ...     │
│ ──────────────── │
│ 节点组     [+新建] │  GroupPalette (200px)
│  🟢 Spine ×100   │
│  ⚪ Leaf  ×480   │
└──────────────────┘
```

### 2. 画布展示范围

画布上只展示**普通节点**和**宏节点**。宏节点是一个可视化占位符，代表整个节点组。**不展示已展开的组内个体节点，也不提供组内分页视图**。

```
画布展示：
  ✅ 手动创建的普通节点（从 TypePalette 拖入）
  ✅ 宏节点（从 GroupPalette 拖入 / 创建组后自动出现）
  ✅ 普通边（普通节点之间）
  ✅ 宏边（宏节点之间的策略边）
  ❌ 已展开的组内个体节点（不在画布上渲染，无处浏览）
```

> **关于 materialize：** 展开操作仍在后端创建实体节点到 DB，目的是支持混合连线（普通节点 ↔ 宏节点的 all_to_all 边需要目标组已展开）。个体节点仅作为数据存在，前端不提供浏览入口。

### 3. 拖拽行为

| 拖拽来源 | 目标 | 行为 |
|---|---|---|
| TypePalette 设备 | 画布 | 弹出 NodeAttrsModal → 创建普通节点 |
| GroupPalette 组 | 画布 | 宏节点定位到放置坐标 |

两种拖拽互不干扰，`handleDrop` 根据 MIME 类型分发。

### 4. 单击 / 双击

| 对象 | 单击 | 双击 |
|---|---|---|
| 普通节点 | 选中（高亮边框） | 打开 NodeAttrsPanel |
| 宏节点 | 选中（高亮边框） | 无操作（无组内视图） |
| 普通边 | 选中（变色） | 打开 EdgeAttrsPanel |
| 宏边 | 选中（变色） | 弹出边策略编辑弹窗 |

### 5. 连线模式

工具栏点击"连线"→ 点击源 → 点击目标 → 根据类型组合自动分发：

| 源 | 目标 | 行为 |
|---|---|---|
| 普通节点 | 普通节点 | 选边类型 → 创建实体 edge（与普通连线模式相同，无需改动） |
| 宏节点 | 宏节点 | 选边类型 + 模式 → 更新源组 edgeStrategies |
| 普通节点 | 宏节点 | **混合连接** → all_to_all 全连接策略 |
| 宏节点 | 普通节点 | **混合连接** → all_to_all 全连接策略 |

混合连接：将普通节点视为单节点"组"，与宏节点下所有已展开节点建立全连接边。该连接仅存储为边策略，不在画布上渲染个体边。

### 6. 右键菜单

GroupPalette 中每个组右键弹出菜单：

| 菜单项 | 条件 | 行为 |
|---|---|---|
| 展开到画布 | 未展开 | POST materialize → 刷新画布 |
| 编辑组定义 | 始终 | 打开 GroupCreateModal（编辑模式） |
| 删除此组 | 始终 | Modal.confirm 级联删除 |
| 缩放到此组 | 始终 | 画布聚焦该宏节点 |

### 7. 画布删除

支持通过键盘 Delete / Backspace 删除画布上已选中的任意元素。

**选中逻辑：** 单击任意画布元素（普通节点 / 宏节点 / 普通边 / 宏边 / 混合边）将其设为当前选中项，显示高亮边框。双击行为不受影响。

**删除行为：**

| 选中元素 | 按键 | 行为 |
|----------|------|------|
| 普通节点 | Delete / Backspace | Modal.confirm → DELETE /nodes/{id} → 移除节点 + 级联移除相连边 |
| 普通边 | Delete / Backspace | Modal.confirm → DELETE /edges/{id} → 移除边 |
| **宏节点** | Delete / Backspace | Modal.confirm → DELETE /node-groups/{id}（级联删除组内全部节点和边）→ 移除宏节点 + 关联宏边 |
| **宏边** | Delete / Backspace | Modal.confirm → 从源组 edgeStrategies 中删除对应规则 → PUT 更新组 → 刷新 groupGraph → 移除画布边 |
| **混合边** | Delete / Backspace | Modal.confirm → 从源组 edgeStrategies 中删除对应规则 → PUT 更新组 → 刷新 groupGraph → 移除画布边 |

**冲突处理：** 输入框/文本域中按下 Delete/Backspace 时不触发画布删除（与普通节点删除一致）。

## 物化引擎（Materialize）

### 核心流程

```
POST /node-groups/{id}/materialize
  1. 校验：组是否存在、是否已展开（已展开返回 409）
  2. 读取组定义（nodeCount, attrStrategies, edgeStrategies）
  3. 遍历 nodeCount 次，逐条生成 node + node_attrs，每 5000 条 flush 到 DB
  4. 遍历 edgeStrategies，按模式生成边，逐条写入 edges + edge_attrs
  5. 每个 flush 批次通过 WS 推送进度
  6. 返回 { materializedNodes, materializedEdges, elapsedMs }
```

### 属性生成策略

每组属性策略绑定到一个 `node_type_field.fieldKey`，根据策略类型计算值：

| 策略 | 参数 | 算法 | 示例 |
|---|---|---|---|
| `fixed` | `fixedValue` | 所有节点使用同一固定值 | `vendor = "Huawei"` |
| `random` | `pool[]` | 每个节点从候选池随机选取（seeded random 保证可复现） | `vendor ∈ ["Huawei","Cisco","H3C"]` |
| `increment` | `base`, `step` | 第 i 个节点值 = base + (i-1) × step | `ip = 10.0.0.1, 10.0.0.2, ...` |
| `range` | `min`, `max` | 每个节点在 [min, max] 内随机取整数 | `cpu ∈ [4, 64]` |

### 边生成策略

每条边策略指定源组与目标组的连接方式：

| 模式 | 算法 | 边数 |
|---|---|---|
| `modulo` | 第 i 个源节点连接第 `i // ratioK` 个目标节点 | N × 1（每个源 1 条） |
| `one_to_n` | 第 i 个源节点连接 `ratioK` 个目标节点 | N × ratioK |
| `all_to_all` | 源节点全连接目标节点（笛卡尔积） | N × M |
| `dense` | 按序号一对一配对 | min(N, M) |

**边数上限：** 笛卡尔积边数超过 1,000,000 条时返回 400 拦截。

### 命名模板渲染

节点命名格式 `{prefix}-{i:0widthd}`，渲染示例：

```
模板: SW-{i:05d}, nodeCount=3
  → SW-00001, SW-00002, SW-00003

模板: Server-{i:03d}, nodeCount=5
  → Server-001, Server-002, Server-003, Server-004, Server-005
```

### WS 进度推送

```
消息格式: { op: "publish", topic: "group.materialize.progress", payload: {
  topologyId, groupId,
  phase: "nodes" | "edges" | "done",
  current: 3200, total: 10000, pct: 32,
  elapsedMs: 430
}}
```

- `nodes` 阶段：每 5000 条节点 flush 时推送一次
- `edges` 阶段：每 10000 条边 flush 时推送一次
- `done` 阶段：全部完成后推送一次（pct=100）

### 并发控制

同一节点组同时只允许一个 materialize 请求。使用模块级 `_materialize_locks: dict[str, bool]` 字典实现互斥，请求开始时加锁、完成/异常时释放。

## 数据模型

### 数据库

```sql
CREATE TABLE node_groups (
  id              TEXT PRIMARY KEY,
  topology_id     TEXT NOT NULL,
  node_type_id    TEXT NOT NULL,
  group_name      TEXT NOT NULL,
  node_count      INTEGER NOT NULL CHECK (node_count > 0),
  name_template   TEXT NOT NULL DEFAULT '{group}-{i:05d}',
  attr_strategies TEXT NOT NULL DEFAULT '[]',
  edge_strategies TEXT,
  created_at      TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at      TEXT NOT NULL DEFAULT (datetime('now')),
  FOREIGN KEY (topology_id) REFERENCES topologies(id) ON DELETE CASCADE,
  FOREIGN KEY (node_type_id) REFERENCES node_types(id)
);

ALTER TABLE nodes ADD COLUMN group_id TEXT;
```

### API 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/topologies/{id}/node-groups` | 列出拓扑下所有组 |
| POST | `/topologies/{id}/node-groups` | 创建组 |
| PUT | `/node-groups/{id}` | 编辑组定义（含 edgeStrategies 追加） |
| DELETE | `/node-groups/{id}` | 删除组 + 级联删节点 |
| POST | `/node-groups/{id}/materialize` | 展开为实体节点 |
| GET | `/topologies/{id}/group-graph` | 宏节点 + 宏边数据（画布渲染用） |

```typescript
export const nodeGroupApi = {

```

### D2 物化引擎：materialize + WS 进度 | `node_group.py` + `ws_hub.py` | 1.5h

| # | 验收项 | 验证方式 |
|---|--------|---------|
| 1 | 展开未展开的组：生成 `nodeCount` 个节点 | 创建 100 节点组 → materialize → `SELECT COUNT(*) FROM nodes WHERE group_id = ?` 返回 100 |
| 2 | 节点命名按 `nameTemplate` 生成 | 模板 `SW-{i:05d}` → 首节点 `SW-00001`，末节点 `SW-00100` |
| 3 | 属性 `fixed` 策略：所有节点该属性值相同 | 100 个节点 model 字段全等于指定值 |
| 4 | 属性 `random` 策略：节点值从候选池中选取（seeded random 可复现） | 100 个节点 vendor 字段全部来自候选池，至少出现 2 种不同值 |
| 5 | 属性 `increment` 策略：节点值按步长递增 | `ip = 10.0.0.1, 10.0.0.2, ..., 10.0.0.100` |
| 6 | 属性 `range` 策略：节点值在 [min, max] 范围内 | 所有 cpu 值在 4~64 之间 |
| 7 | 边 `modulo` 模式：每 K 个源连 1 个目标 | 源 100→目标 10，ratioK=10 → 源 1-10 连目标 1 |

## 设计决策说明

| 决策 | 选择 | 理由 |
|---|---|---|
| 画布架构 | 单画布（TopologyCanvas），不引入 MacroCanvas | 避免多画布切换的 viewMode 状态机和组件间状态同步问题 |
| 宏节点定位 | 共存于 TopologyCanvas，自定义 Shape 区分 | 用户无需切换模式即可同时看到普通节点和节点组 |
| 组内节点展示 | 不提供组内分页视图 | 宏节点作为抽象占位符已足够；个体节点数据仅用于支撑混合连线 |
| 左侧面板 | TypePalette + GroupPalette 始终同时显示 | 避免按模式显隐带来的条件分支和用户困惑 |
| 右侧面板 | 仅保留 NodeAttrsPanel + EdgeAttrsPanel | 宏节点无可编辑属性，不需要专用面板；展开操作通过 GroupPalette 右键菜单完成 |
| Composable 共享 | CanvasView provide 单例 | 消除多组件独立实例导致的数据不同步（每个组件各自 fetch 但状态不互通） |
| 连线模式 | 根据节点类型自动分发，支持混合连接 | 单画布下同一连线按钮需处理 4 种组合，混合连接用 all_to_all 策略 |
| 文件策略 | 新增 2 个文件，不删除已有组件 | 最小侵入原则，其余组件仅做扩展不改核心逻辑 |
